Every system in a Ritmo game declares what it reads, writes, and spawns.
So the game can print itself: here is the [top-down demo](/docs/browser/)
describing its own update, from `session.describe()`:

```text title="session.describe(), an excerpt"
update:
   0 TopDown/CaptureFrameContext
   1 TopDown/CaptureInput
   2 TopDown/PlanPlayerVelocity
   3 TopDown/MovePlayer
   4 TopDown/UpdateFocusedCollectable
   5 TopDown/CollectFocusedCollectable
   6 TopDown/ResolveFacing
   7 TopDown/ResolveLocomotion
   8 <applyDeferred>
   9 <applyStateTransitions>

TopDown/MovePlayer  @ update#3
  query player: read TopDown/Collider, TopDown/Player; write TopDown/Position, TopDown/Velocity
  query walls: read TopDown/Position, TopDown/Collider, TopDown/Wall
  reads resources: TopDown/DeltaTime
TopDown/CollectFocusedCollectable  @ update#5
  query collectables: read TopDown/Position, TopDown/Collider, TopDown/Collectable
  reads resources: TopDown/InputState
  writes resources: TopDown/FocusedCollectable, TopDown/CollectedCount
  may despawn: TopDown/Collectable
```

The compiler checks each system against those declarations, the schedule
checks the order, and the devtools read them to explain a run. This page
builds one small arena with every piece. After it, you can read any Ritmo
game and know where each piece lives.

A Ritmo game is a **world** of entities, **systems** that change it, and
**schedules** that run them in a checked order, one fixed step at a time.
Hover any name for its type.

## The world

Components belong to entities, resources to the whole world, and events are
messages between systems. Each has a unique name and a type. `Schema.bind`
turns them into `Game`, and every other API comes from `Game`.

```ts twoslash title="schema.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"

// Components: data on an entity. An empty one is a tag.
const Position = Descriptor.Component<{ x: number; y: number }>()(
  "Arena/Position"
)
const Health = Descriptor.Component<number>()("Arena/Health")
const Enemy = Descriptor.Component<{}>()("Arena/Enemy")

// A resource: one value for the whole world
const Score = Descriptor.Resource<number>()("Arena/Score")

// An event: a message read by the systems that ask for it
const Hit = Descriptor.Event<{ amount: number }>()("Arena/Hit")

const Game = Schema.bind(
  Schema.fragment({
    components: { Position, Health, Enemy },
    resources: { Score },
    events: { Hit }
  })
)
```

## Systems

A system's spec declares everything it touches, and its function gets only
that. The runtime, the devtools, and the schedule checks all read the same
spec.

```ts twoslash title="damage.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Health = Descriptor.Component<number>()("Arena/Health")
const Enemy = Descriptor.Component<{}>()("Arena/Enemy")
const Score = Descriptor.Resource<number>()("Arena/Score")
const Hit = Descriptor.Event<{ amount: number }>()("Arena/Hit")
const Game = Schema.bind(Schema.fragment({ components: { Position, Health, Enemy }, resources: { Score }, events: { Hit } }))
// ---cut---
const Damage = Game.System(
  "Arena/Damage",
  {
    // Writes the health of every enemy... // [!code focus]
    queries: { // [!code focus]
      enemies: Game.Query({ // [!code focus]
        selection: { health: Game.Query.write(Health) }, // [!code focus]
        with: [Enemy] // [!code focus]
      }) // [!code focus]
    }, // [!code focus]
 // [!code focus]
    // ...and reads this tick's hits // [!code focus]
    events: { hits: Game.System.readEvent(Hit) } // [!code focus]
  },

  ({ queries, events }) => {
    for (const hit of events.hits.all()) {
      for (const { data } of queries.enemies.each()) {
        data.health.set(data.health.get() - hit.amount)
      }
    }
  }
)
```

## Queries

`selection` is the data each match gets, `with` and `without` filter by
component, and `changed` keeps only what changed since this system last ran.

Every read in Ritmo works this way: changes, events, and transitions are
streams per reader. Each system sees what was published since its own
previous run, once.

```ts twoslash title="queries.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Health = Descriptor.Component<number>()("Arena/Health")
const Enemy = Descriptor.Component<{}>()("Arena/Enemy")
const Game = Schema.bind(Schema.fragment({ components: { Position, Health, Enemy } }))
// ---cut---
const Wounded = Game.Query({
  // The data each match gets
  selection: {
    position: Game.Query.read(Position),
    health: Game.Query.read(Health)
  },

  // Only enemies, and only when their health changed since this system last ran
  with: [Enemy],
  filters: [Game.Query.changed(Health)] // [!code highlight]
})
```

## Commands

Spawns, despawns, inserts, and removes are queued, and they land together at
the next `applyDeferred()`. No system sees the world change shape while it
runs.

```ts twoslash title="waves.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Health = Descriptor.Component<number>()("Arena/Health")
const Enemy = Descriptor.Component<{}>()("Arena/Enemy")
const Game = Schema.bind(Schema.fragment({ components: { Position, Health, Enemy } }))
const Enemies = Game.Query({ selection: { health: Game.Query.read(Health) }, with: [Enemy] })
// ---cut---
const Cull = Game.System(
  "Arena/Cull",
  {
    queries: { enemies: Enemies },

    // The only command this system may queue
    commands: Game.System.commands(Game.System.despawns(Enemy)) // [!code highlight]
  },

  ({ queries, commands }) => {
    for (const match of queries.enemies.each()) {
      // match.entity proves this is an Enemy: a raw id would not compile
      if (match.data.health.get() <= 0) commands.despawn(match.entity) // [!code highlight]
    }
  }
)
```

## Schedules and the tick

A schedule lists the systems in order and marks where commands land. A tick
returns a `Result`. If a system fails, its writes are rolled back and the
tick names the system.

```ts twoslash title="update.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Health = Descriptor.Component<number>()("Arena/Health")
const Enemy = Descriptor.Component<{}>()("Arena/Enemy")
const Hit = Descriptor.Event<{ amount: number }>()("Arena/Hit")
const Game = Schema.bind(Schema.fragment({ components: { Position, Health, Enemy }, events: { Hit } }))
const SpawnWave = Game.System("Arena/SpawnWave", { commands: Game.System.commands(Game.System.spawns(Position, Health, Enemy)) }, () => {})
const Damage = Game.System("Arena/Damage", { queries: { enemies: Game.Query({ selection: { health: Game.Query.write(Health) }, with: [Enemy] }) }, events: { hits: Game.System.readEvent(Hit) } }, () => {})
const Cull = Game.System("Arena/Cull", { queries: { enemies: Game.Query({ selection: { health: Game.Query.read(Health) }, with: [Enemy] }) }, commands: Game.System.commands(Game.System.despawns(Enemy)) }, () => {})
const made = Game.Runtime.make({ services: Game.Runtime.services() })
if (!made.ok) throw new Error()
const runtime = made.value
// ---cut---
// Systems run in this order; queued commands land at applyDeferred()
const update = Game.Schedule(
  SpawnWave,
  Damage,
  Cull,
  Game.Schedule.applyDeferred() // [!code highlight]
)

const ticked = runtime.tick(update)
//    ^?
```

## State machines

A game-wide mode is a state machine: a closed list of states, each with
only its own data.

```ts twoslash title="flow.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
const Health = Descriptor.Component<number>()("Arena/Health")
const Game = Schema.bind(Schema.fragment({ components: { Health } }))
// ---cut---
// A closed list of states, each with the data only it has
const Flow = Game.StateMachine("Arena/Flow", {
  Menu: {},
  Playing: {},
  GameOver: codec(S.Struct({ winner: S.String }))
})

// Asks for the next state, with its data...
const EndRound = Game.System(
  "Arena/EndRound",
  { nextMachines: { flow: Game.System.nextState(Flow) } },
  ({ nextMachines }) =>
    nextMachines.flow.set({ _tag: "GameOver", winner: "Red" }) // [!code highlight]
)

// ...and this one runs only while playing
const Simulate = Game.System(
  "Arena/Simulate",
  { when: [Game.Condition.inState(Flow, "Playing")] }, // [!code highlight]
  () => {}
)
```

The change applies at `applyStateTransitions()`, the state and its data
together. A game over always has a winner, and nothing else does. See
[States that can't go wrong](/features/states/).

## Validating and saving values

Ritmo validates with the schema library your game already uses: any
[Standard Schema](https://standardschema.dev), from Zod, Valibot, ArkType,
or Effect. A constructed descriptor takes one. Raw input and saves are
checked by it.

`runtime.snapshot()` saves each value in its schema's encoded form. A
schema of plain data passes as it is. A value that changes shape when saved
(a `Map`, an `Option`, a `Date`) needs a schema with a `"~encode"` back, and
the descriptor does not compile without one.

The skill has a helper for Zod and one for Effect. With Effect, one helper
in the game turns any schema into that shape:

```ts twoslash title="codec.ts"
import { Descriptor, Entity, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"

// Decodes saved JSON, and encodes values back to it
type Plain = S.Top & {
  readonly DecodingServices: never
  readonly EncodingServices: never
}
const codec = <T extends Plain>(schema: T) => {
  const json = S.toCodecJson(schema)
  return {
    "~standard": S.toStandardSchemaV1(json)["~standard"],
    "~encode": S.toStandardSchemaV1(S.flip(json))
  }
}

const Root = Schema.defineRoot("Arena")
const Health = Descriptor.ConstructedComponent(codec(S.Finite))("Arena/Health")

// Saved as [["potion", 3]], loaded back as a Map
const Stock = Descriptor.ConstructedResource(
  codec(S.ReadonlyMap(S.String, S.Int))
)("Arena/Stock")

// Ritmo's own types come with a guard to build a schema from
const Target = Descriptor.ConstructedComponent(codec(S.Struct({
  enemy: S.declare(Entity.isHandle(Root, Health))
})))("Arena/Target")

const Game = Schema.bind(
  Schema.fragment({ components: { Health, Target }, resources: { Stock } }),
  Root
)
const runtime = Game.Runtime.make({
  services: Game.Runtime.services(),
  resources: { Stock: [["potion", 3]] }
})
if (runtime.ok) {
  // Encoding can fail, so a snapshot is a Result
  const saved = runtime.value.snapshot()
  //    ^?
}
```

## Same input, same game

The simulation advances in fixed steps (`Clock.hz(60)`). Time comes from
`Clock`, randomness from a seeded `Random`, and trigonometry from `Ops`. The
lint rules reject `Math.random`, `Date.now`, and page APIs inside systems.

That makes a run exact: replays, [headless tests](/docs/devtools/), and
[online play](/features/rollback/) all rely on it. See [Same game
everywhere](/features/determinism/).
