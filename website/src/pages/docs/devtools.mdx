Your game runs in Node with scripted input, with no page and no renderer.
`@typeonce/ritmo-devtools` records every write, so a run answers questions
in plain text: which rule broke, on which frame, and which system wrote the
wrong value.

After this page you can reproduce a bug in a script, check a rule every
frame, and read why a value changed. An agent debugs the same way.

```sh
pnpm add -D @typeonce/ritmo-devtools
```

## A scripted run

This runs 120 frames of the [top-down demo](/docs/browser/) with a scripted
keyboard. The **invariant** is checked every frame, and the run stops at the
first frame that breaks it.

```ts twoslash title="debug.ts"
import { HostClock } from "@typeonce/ritmo"
import { Gamepad, Keyboard, Pointer } from "@typeonce/ritmo-browser"
import { Invariant, Session } from "@typeonce/ritmo-devtools"
import {
  PlayerPositionQuery
} from "@typeonce/ritmo-integration-top-down/queries.ts"
import { Game, Position } from "@typeonce/ritmo-integration-top-down/schema.ts"
import {
  createTopDownSimulation
} from "@typeonce/ritmo-integration-top-down/simulation.ts"
import {
  inputBindings,
  mouseBindings,
  padBindings
} from "@typeonce/ritmo-integration-top-down/types.ts"

const keyboard = Keyboard.scripted(inputBindings, [
  { frame: 0, press: ["move.up", "move.left"] },
  { frame: 40, release: ["move.up"] },
  { frame: 50, press: ["interact"], release: ["interact"] }
])

// A test clock keeps every timing at 0, so the output is the same each run
const hostClock = HostClock.test()
const mouse = Pointer.scripted(mouseBindings, [])
const gamepad = Gamepad.scripted(padBindings, [])
const simulation = createTopDownSimulation({
  keyboard,
  mouse,
  gamepad,
  hostClock
})
if (!simulation.ok) throw new Error(simulation.error.message)
const { runtime, setup, update } = simulation.value

// Returns a message when the rule is broken, undefined while it holds.
const PlayerInsideWorld = Invariant.fromInspector(
  Game.Inspector(
    "player inside world",
    { queries: { player: PlayerPositionQuery } },
    ({ queries }) => {
      for (const match of queries.player.each()) {
        const { x, y } = match.data.position.get()
        if (x < 0 || x > 2200 || y < 0 || y > 1600)
          return `player at (${x}, ${y})`
      }
      return undefined
    }
  )
)

const session = Session.make(runtime, {
  hostClock,
  schedules: { setup, update },
  invariants: [PlayerInsideWorld] // [!code highlight]
})

session.run("setup")
session.run("update", { frames: 120 })
console.log(session.why(1, Position)) // [!code highlight]
```

## Asking why

`session.why(1, Position)` prints the latest changes to the player's
position, each with its frame, schedule, and system (long lines wrapped
here):

```text
e1 TopDown/Position is now {x:134.673,y:128.007}; last 5 changes (oldest first):
could have spawned it: TopDown/SetupWorld
f117 update  TopDown/MovePlayer  write e1 TopDown/Position
  {x:158.007,y:128.007} -> {x:153.34,y:128.007}
f118 update  TopDown/MovePlayer  write e1 TopDown/Position
  {x:153.34,y:128.007} -> {x:148.673,y:128.007}
f119 update  TopDown/MovePlayer  write e1 TopDown/Position
  {x:148.673,y:128.007} -> {x:144.007,y:128.007}
f120 update  TopDown/MovePlayer  write e1 TopDown/Position
  {x:144.007,y:128.007} -> {x:139.34,y:128.007}
f121 update  TopDown/MovePlayer  write e1 TopDown/Position
  {x:139.34,y:128.007} -> {x:134.673,y:128.007}
```

Sometimes the system that wrote the value only passed on a wrong input.
Raise `depth`, and under each change it lists what that system declared it
reads and which system produced each, one system further back per step.

These are possible causes read from declarations, so each such line says
`(declared)`:

```text
f181 update  Game/ApplyDamage  write e12 Game/Health 70 -> 40
  read Game/Damage [{amount:30}] (declared), emitted by Game/Hitscan at f181
    read resource Game/Aim {target:12} (declared),
      written by Game/AimAtNewest at f180
```

Other questions a session answers:

| Call | Answers |
|---|---|
| `session.describe()` | The schema, every schedule step, and who reads and writes each component, resource, and event, with lints first |
| `session.report()` | Warnings, time per system, and how many entities have each component |
| `session.dump({ with: [Player] })` | The entities, resources, and state machines right now |
| `session.whyResource(Score)` | The latest changes to a resource |
| `session.journal({ frames: [100, 120], entity })` | Everything that touched an entity in a range of frames |
| `session.step("update")` | One frame a system at a time: `until(MovePlayer)` stops before it, `next()` runs one step, `finish()` reports the frame like `run` |

## Lints

Some code compiles and is still probably wrong: an event nobody reads, a
state never applied, a one-frame lag. `describe()` lists these lints first:

```text
# Lints
info command-permission-unused: TopDown/CollectFocusedCollectable may
despawn TopDown/Collectable but never did in this session
```

Two commands run them in the game's check:

```sh
# Schedule lints, fails on a warning
ritmo-devtools lint src/simulation.ts
# @typeonce/oxlint-plugin-ritmo: no Math.random, Date.now, DOM in systems
oxlint
```

## Same input, same game

`Determinism.check` runs the same script twice and reports the first frame,
value, and system that diverged. `ritmo-devtools verify` plays a recorded
replay in Node, Chromium, WebKit, and Firefox and names the first tick they
disagree on. See [Same game
everywhere](/features/determinism/).

## From a script to a test

A scripted run with an invariant is already most of a test. The fuzzer goes
further: it writes the input itself, plays until an invariant breaks, and
shrinks the failure to a replay you keep as a test. See [Bugs found before
players](/features/bugs/) and [Replays that become
tests](/features/replays/).
