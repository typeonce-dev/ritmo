By the end of this page you have a world, an entity that moves, and a loop
that runs it for one second of game time. The same code runs in a test, in
Node, and on a page.

Hover any name in the code to see its type.

## Install

```sh
pnpm add @typeonce/ritmo
```

Ritmo needs TypeScript 5.9 or newer with `strict` on. The add-ons are
released with the same version, and you install them when the game needs
them:

| Package | What it gives you |
|---|---|
| `@typeonce/ritmo` | The runtime, the fixed step, seeded `Random`, and `Ops` math that returns the same bits everywhere |
| `@typeonce/ritmo-math` | 2D helpers on plain data: vectors, angles, swept circles, a flow field |
| `@typeonce/ritmo-browser` | The browser loop, keyboard, gamepad, pointer, and touch input |
| `@typeonce/ritmo-render` | One renderer node per entity, kept in sync |
| `@typeonce/ritmo-pixi` | The Pixi adapter for `ritmo-render` |
| `@typeonce/ritmo-netcode` | [Online multiplayer](/features/rollback/) with rollback or lockstep |
| `@typeonce/ritmo-devtools` | Headless sessions, the fuzzer, determinism checks, `ritmo-devtools lint` |
| `@typeonce/oxlint-plugin-ritmo` | Lint rules that keep game logic deterministic and headless |

Working with a coding agent? [Set the project up with
it](/docs/with-an-agent/) instead: it installs the checks too.

## Describe the world

A component is data an entity carries. A resource is one value for the
whole world, here the clock. `Schema.bind` turns them into `Game`, and every
other API comes from `Game`.

```ts twoslash title="schema.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"

type Vec = { x: number; y: number }

// 60 fixed steps per second, whatever the frame rate
const step = Clock.hz(60)
const Time = Clock.resource("Example/Time", step)

// What an entity can carry
const Position = Descriptor.Component<Vec>()("Example/Position")
const Velocity = Descriptor.Component<Vec>()("Example/Velocity")

const Game = Schema.bind(
  Schema.fragment({
    components: { Position, Velocity },
    resources: { Time }
  })
)
```

## Write two systems

A system declares what it touches, and its function gets only that. `Move`
writes `Position` and reads `Velocity` and the clock. Writing `Velocity`
from it would not compile.

```ts twoslash title="move.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"
type Vec = { x: number; y: number }
const step = Clock.hz(60)
const Time = Clock.resource("Example/Time", step)
const Position = Descriptor.Component<Vec>()("Example/Position")
const Velocity = Descriptor.Component<Vec>()("Example/Velocity")
const Game = Schema.bind(Schema.fragment({ components: { Position, Velocity }, resources: { Time } }))
// ---cut---
const Move = Game.System(
  "Example/Move",
  {
    queries: {
      moving: Game.Query({
        selection: {
          position: Game.Query.write(Position), // [!code highlight]
          velocity: Game.Query.read(Velocity) // [!code highlight]
        }
      })
    },
    resources: { time: Game.System.readResource(Time) }
  },
  ({ queries, resources }) => {
    const { dt } = resources.time.get()
    for (const match of queries.moving.each()) {
      const position = match.data.position.get()
      const velocity = match.data.velocity.get()
      //    ^?
      match.data.position.set({
        x: position.x + velocity.x * dt,
        y: position.y + velocity.y * dt
      })
    }
  }
)
```

`Spawn` creates the entity. It may spawn only the components it lists, and
the spawn is queued: it lands at the next `applyDeferred()`, so no system
sees the world change shape halfway through.

```ts twoslash title="spawn.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"
type Vec = { x: number; y: number }
const step = Clock.hz(60)
const Time = Clock.resource("Example/Time", step)
const Position = Descriptor.Component<Vec>()("Example/Position")
const Velocity = Descriptor.Component<Vec>()("Example/Velocity")
const Game = Schema.bind(Schema.fragment({ components: { Position, Velocity }, resources: { Time } }))
// ---cut---
const Spawn = Game.System(
  "Example/Spawn",
  {
    commands: Game.System.commands(
      Game.System.spawns(Position, Velocity) // [!code highlight]
    )
  },
  ({ commands }) => {
    commands.spawn(
      Game.Command.spawn(
        [Position, { x: 0, y: 0 }],
        [Velocity, { x: 30, y: 0 }]
      )
    )
  }
)
```

## Run the first tick

A schedule lists systems in order. Making a runtime and running a tick each
return a `Result`, so a failure is a value you check, never an exception.

```ts twoslash title="main.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"
type Vec = { x: number; y: number }
const step = Clock.hz(60)
const Time = Clock.resource("Example/Time", step)
const Position = Descriptor.Component<Vec>()("Example/Position")
const Velocity = Descriptor.Component<Vec>()("Example/Velocity")
const Game = Schema.bind(Schema.fragment({ components: { Position, Velocity }, resources: { Time } }))
const Move = Game.System("Example/Move", { queries: { moving: Game.Query({ selection: { position: Game.Query.write(Position), velocity: Game.Query.read(Velocity) } }) }, resources: { time: Game.System.readResource(Time) } }, () => {})
const Spawn = Game.System("Example/Spawn", { commands: Game.System.commands(Game.System.spawns(Position, Velocity)) }, () => {})
// ---cut---
// Moves the clock forward one step per tick
const AdvanceTime = Clock.system(Game, {
  name: "Example/AdvanceTime",
  resource: Time
})

const setup = Game.Schedule(Spawn, Game.Schedule.applyDeferred())
const update = Game.Schedule(AdvanceTime, Move)

// Every service and resource the schedules need, given up front
const made = Game.Runtime.make({
  services: Game.Runtime.services(),
  resources: { Time: Clock.start(step) }
})

if (made.ok) {
  const runtime = made.value
  runtime.tick(setup)

  // One second of game time
  for (let frame = 0; frame < 60; frame++) {
    const ticked = runtime.tick(update) // [!code highlight]
    if (!ticked.ok) console.error(ticked.error)
  }
}
```

## Read the world

An inspector declares reads like a system, and `runtime.inspect` returns
what it computes. Tests, UIs, and saves read the world this way.

```ts twoslash title="main.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"
type Vec = { x: number; y: number }
const step = Clock.hz(60)
const Time = Clock.resource("Example/Time", step)
const Position = Descriptor.Component<Vec>()("Example/Position")
const Velocity = Descriptor.Component<Vec>()("Example/Velocity")
const Game = Schema.bind(Schema.fragment({ components: { Position, Velocity }, resources: { Time } }))
const made = Game.Runtime.make({ services: Game.Runtime.services(), resources: { Time: Clock.start(step) } })
if (!made.ok) throw new Error()
const runtime = made.value
// ---cut---
const Positions = Game.Inspector(
  "Example/Positions",
  {
    queries: {
      all: Game.Query({ selection: { position: Game.Query.read(Position) } })
    }
  },
  ({ queries }) =>
    Array.from(queries.all.each(), (match) => match.data.position.get())
)

// After the sixty ticks above
console.log(runtime.inspect(Positions))
```

```text
[ { x: 30, y: 0 } ]
```

Thirty units per second for sixty steps of 1/60 s: the entity is at 30, on
every machine, every run.
