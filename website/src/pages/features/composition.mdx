The schema lists every kind of component a game has. Which ones an entity
holds changes all game long: a guard gets stunned and recovers, a sword is
put in a hand, an archer picks a target.

## Add and remove at runtime

A system inserts and removes components with commands, and its spec says
which ones. Here a hit stuns every guard that is not stunned already:

```ts twoslash title="stun.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"

const Velocity = Descriptor.Component<{ x: number; y: number }>()("Arena/Velocity")
const Guard = Descriptor.Component<{}>()("Arena/Guard")
const Stunned = Descriptor.Component<{ frames: number }>()("Arena/Stunned")
const Hit = Descriptor.Event<{ amount: number }>()("Arena/Hit")

const Game = Schema.bind(Schema.fragment({ components: { Velocity, Guard, Stunned }, events: { Hit } }))
// ---cut---
// @errors: 2345
const Stun = Game.System(
  "Arena/Stun",
  {
    queries: {
      guards: Game.Query({ selection: {}, with: [Guard], without: [Stunned] })
    },
    events: { hits: Game.System.readEvent(Hit) },

    // The only component this system may add
    commands: Game.System.commands(Game.System.inserts(Stunned)) // [!code highlight]
  },

  ({ queries, events, commands }) => {
    if (events.hits.all().length === 0) return
    for (const match of queries.guards.each()) {
      commands.insert(match.entity, [Stunned, { frames: 30 }])

      // Not declared, so it does not compile
      commands.insert(match.entity, [Velocity, { x: 0, y: 0 }])
    }
  }
)
```

Removing works the same way: `Game.System.removes(Stunned)` in the spec,
`commands.remove(match.entity, Stunned)` in the body.

## Every change lands at one point

Inserts, removes, spawns, and despawns are queued and applied together at
the next `applyDeferred()`. While a system runs, no entity gains or loses a
component, so a loop never sees an entity change shape under it. After that
point, queries see the new shape: a movement query with `without: [Stunned]`
skips the guard from then on.

```ts twoslash title="update.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Velocity = Descriptor.Component<{ x: number; y: number }>()("Arena/Velocity")
const Guard = Descriptor.Component<{}>()("Arena/Guard")
const Stunned = Descriptor.Component<{ frames: number }>()("Arena/Stunned")
const Game = Schema.bind(Schema.fragment({ components: { Position, Velocity, Guard, Stunned } }))
const Stun = Game.System("Arena/Stun", { commands: Game.System.commands(Game.System.inserts(Stunned)) }, () => {})
// ---cut---
const Move = Game.System(
  "Arena/Move",
  {
    queries: {
      movers: Game.Query({
        selection: { position: Game.Query.write(Position), velocity: Game.Query.read(Velocity) },
        without: [Stunned] // [!code highlight]
      })
    }
  },
  ({ queries }) => {
    for (const { data } of queries.movers.each()) {
      const { x, y } = data.position.get()
      const velocity = data.velocity.get()
      data.position.set({ x: x + velocity.x, y: y + velocity.y })
    }
  }
)

// The stun lands at applyDeferred(): this tick the guard still moves, the next it does not
const update = Game.Schedule(Stun, Move, Game.Schedule.applyDeferred())
```

## Reacting to a change

A query with `Game.Query.added(Stunned)` matches the entities that gained
the component since this system last ran, and `Game.System.readRemoved`
lists the ones that lost it. Each system sees each change once, on its own
next run.

```ts twoslash title="feedback.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Stunned = Descriptor.Component<{ frames: number }>()("Arena/Stunned")
const Game = Schema.bind(Schema.fragment({ components: { Stunned } }))
// ---cut---
const Feedback = Game.System(
  "Arena/Feedback",
  {
    queries: {
      dazed: Game.Query({
        selection: { stunned: Game.Query.read(Stunned) },
        filters: [Game.Query.added(Stunned)] // [!code highlight]
      })
    },
    removed: { recovered: Game.System.readRemoved(Stunned) } // [!code highlight]
  },
  ({ queries, removed }) => {
    for (const match of queries.dazed.each()) {
      // show stars over match.entity
    }
    for (const entityId of removed.recovered.all()) {
      // clear the stars
    }
  }
)
```

## A sword in a hand

`Descriptor.Hierarchy` links a child to its parent. The runtime keeps the
reverse side (the parent's children) in step, keeps the children in order,
and despawns them with their parent.

```ts twoslash title="arm.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Hand = Descriptor.Component<{}>()("Arena/Hand")
// ---cut---
// The edge, and the reverse side the runtime maintains
const { relation: ChildOf } = Descriptor.Hierarchy("Arena/ChildOf", "Arena/Children")

const Game = Schema.bind(Schema.fragment({
  components: { Position, Hand },
  relations: { ChildOf } // [!code highlight]
}))

const Arm = Game.System(
  "Arena/Arm",
  { commands: Game.System.commands(Game.System.spawns(Position, Hand), Game.System.relates(ChildOf)) },
  ({ commands }) => {
    const hand = commands.spawn(Game.Command.spawn([Position, { x: 0, y: 0 }], [Hand, {}]))

    // The sword is spawned already in the hand
    commands.spawn(
      Game.Command.relate(Game.Command.spawn([Position, { x: 4, y: 0 }]), ChildOf, hand) // [!code highlight]
    )
  }
)
```

Following an edge returns a `Result`, because the parent may be gone by the
time a system asks. A link the runtime refuses, such as an entity parented
to itself or a cycle, does not throw: it becomes a typed failure that any
system can read.

```ts twoslash title="follow.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const { relation: ChildOf } = Descriptor.Hierarchy("Arena/ChildOf", "Arena/Children")
const Game = Schema.bind(Schema.fragment({ components: { Position }, relations: { ChildOf } }))
// ---cut---
const Follow = Game.System(
  "Arena/Follow",
  {
    queries: {
      held: Game.Query({ selection: { position: Game.Query.read(Position) }, withRelations: [ChildOf] })
    },
    relationFailures: { childOf: Game.System.readRelationFailures(ChildOf) }
  },
  ({ queries, lookup, relationFailures }) => {
    for (const item of queries.held.each()) {
      const hand = lookup.parent(item.entity.id, ChildOf)
      if (!hand.ok) {
        const missing = hand.error._tag
        //    ^?
        continue
      }
      // hand.value is the parent's id: read it through a declared query
    }

    for (const failure of relationFailures.childOf.all()) {
      const refused = failure.error._tag
      //    ^?
    }
  }
)
```

## Links between any two entities

`Descriptor.Relation` is a plain edge with a reverse lookup and no tree: an
archer targeting a guard, a key opening a door. Despawning the target clears
the edge, so `lookup.related(archer, Targeting)` turns into a
`MissingRelation` failure instead of pointing at an entity that is gone.

```ts twoslash title="schema.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
// ---cut---
const { relation: Targeting } = Descriptor.Relation("Arena/Targeting", "Arena/TargetedBy")
```

The archers do not have to check every tick whether their guard still
exists. Each edge a despawn clears is a record that every system reading it
sees once, so an archer whose guard fell can stand down at that moment.

```ts twoslash title="stand-down.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Idle = Descriptor.Tag("Arena/Idle")
const { relation: Targeting } = Descriptor.Relation("Arena/Targeting", "Arena/TargetedBy")
const Game = Schema.bind(Schema.fragment({ components: { Idle }, relations: { Targeting } }))
// ---cut---
const StandDown = Game.System(
  "Arena/StandDown",
  {
    droppedRelations: { lost: Game.System.readDroppedRelations(Targeting) }, // [!code highlight]
    commands: Game.System.commands(Game.System.inserts(Idle))
  },
  ({ droppedRelations, commands }) => {
    for (const { source } of droppedRelations.lost.all()) {
      commands.insert(source, [Idle, {}])
    }
  }
)
```

## What it buys

- Entities gain and lose components freely, and only the systems that say so
  can do it.
- Changes land at one known point, so no loop sees a half-changed world,
  and each system hears about each change once.
- Trees and links stay consistent: reverse sides, child order, and
  despawning a parent's children are kept by the runtime. A broken link is
  a value to handle, not a crash.
