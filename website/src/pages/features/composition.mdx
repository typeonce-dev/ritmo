A guard gets stunned and recovers. A sword is put in a hand. An archer's
target falls. What an entity holds, and what it is linked to, changes all
game long, and Ritmo keeps each change safe to reason about.

<Game id="composition" ratio="16 / 9" />

One world plays all three, left to right. Under each entity are the
components it holds right now: a change lights up when it lands, and the
line at the bottom of each lane is what a system heard about it.

<Claim title="A system adds only what its spec names">

A stun is a `Stunned` component, inserted by a command. The spec lists the
components a system may insert or remove; any other insert does not
compile.

```ts twoslash title="stun.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"

const Velocity = Descriptor.Component<{ x: number; y: number }>()("Arena/Velocity")
const Guard = Descriptor.Component<{}>()("Arena/Guard")
const Stunned = Descriptor.Component<{ frames: number }>()("Arena/Stunned")
const Hit = Descriptor.Event<{ amount: number }>()("Arena/Hit")

const Game = Schema.bind(Schema.fragment({ components: { Velocity, Guard, Stunned }, events: { Hit } }))
// ---cut---
// @errors: 2345
const Stun = Game.System(
  "Arena/Stun",
  {
    queries: {
      guards: Game.Query({ selection: {}, with: [Guard], without: [Stunned] })
    },
    events: { hits: Game.System.readEvent(Hit) },

    // The only component this system may add
    commands: Game.System.commands(Game.System.inserts(Stunned)) // [!code highlight]
  },

  ({ queries, events, commands }) => {
    if (events.hits.all().length === 0) return
    for (const match of queries.guards.each()) {
      commands.insert(match.entity, [Stunned, { frames: 30 }])

      // Not declared, so it does not compile
      commands.insert(match.entity, [Velocity, { x: 0, y: 0 }])
    }
  }
)
```

Removing works the same way: `Game.System.removes(Stunned)` in the spec,
`commands.remove(match.entity, Stunned)` in the body.

</Claim>

<Claim title="No loop sees an entity change shape under it">

Inserts, removes, spawns, and despawns wait for the next `applyDeferred()`
and land there together. The guard in the demo, tick by tick: the hit's
tick it still moves, and from the next one `Move` skips it.

```text title="the guard, from the demo's world in Node"
tick 30  x 208.0  Guard, Position, Velocity
tick 31  x 209.6  Guard, Position, Velocity, Stunned { frames: 120 }
tick 32  x 209.6  Guard, Position, Velocity, Stunned { frames: 119 }
tick 33  x 209.6  Guard, Position, Velocity, Stunned { frames: 118 }
```

```ts twoslash title="update.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Velocity = Descriptor.Component<{ x: number; y: number }>()("Arena/Velocity")
const Guard = Descriptor.Component<{}>()("Arena/Guard")
const Stunned = Descriptor.Component<{ frames: number }>()("Arena/Stunned")
const Game = Schema.bind(Schema.fragment({ components: { Position, Velocity, Guard, Stunned } }))
const Stun = Game.System("Arena/Stun", { commands: Game.System.commands(Game.System.inserts(Stunned)) }, () => {})
// ---cut---
const Move = Game.System(
  "Arena/Move",
  {
    queries: {
      movers: Game.Query({
        selection: {
          position: Game.Query.write(Position),
          velocity: Game.Query.read(Velocity)
        },
        without: [Stunned] // [!code highlight]
      })
    }
  },
  ({ queries }) => {
    for (const { data } of queries.movers.each()) {
      const { x, y } = data.position.get()
      const velocity = data.velocity.get()
      data.position.set({ x: x + velocity.x, y: y + velocity.y })
    }
  }
)

// The stun lands at applyDeferred(): this tick the guard still moves,
// the next it does not
const update = Game.Schedule(Stun, Move, Game.Schedule.applyDeferred())
```

</Claim>

<Claim title="Each system hears each change once">

`Game.Query.added(Stunned)` matches the entities that gained the component
since this system last ran; `Game.System.readRemoved` lists the ones that
lost it. In the demo the recovery is heard on tick 151, and only then:

```text title="the guard recovering"
tick 150  x 209.6  Guard, Position, Velocity, Stunned { frames: 1 }  heard 0
tick 151  x 209.6  Guard, Position, Velocity  heard 1
tick 152  x 211.2  Guard, Position, Velocity  heard 1
tick 153  x 212.8  Guard, Position, Velocity  heard 1
```

```ts twoslash title="feedback.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Stunned = Descriptor.Component<{ frames: number }>()("Arena/Stunned")
const Game = Schema.bind(Schema.fragment({ components: { Stunned } }))
// ---cut---
const Feedback = Game.System(
  "Arena/Feedback",
  {
    queries: {
      dazed: Game.Query({
        selection: { stunned: Game.Query.read(Stunned) },
        filters: [Game.Query.added(Stunned)] // [!code highlight]
      })
    },
    removed: { recovered: Game.System.readRemoved(Stunned) } // [!code highlight]
  },
  ({ queries, removed }) => {
    for (const match of queries.dazed.each()) {
      // show stars over match.entity
    }
    for (const entityId of removed.recovered.all()) {
      // clear the stars
    }
  }
)
```

</Claim>

<Claim title="A sword goes where its hand goes">

`Descriptor.Hierarchy` links a child to its parent. The runtime keeps the
reverse side (the knight's `Children`) in step, keeps children in order,
and despawns them with their parent.

```ts twoslash title="arm.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Hand = Descriptor.Component<{}>()("Arena/Hand")
// ---cut---
// The edge, and the reverse side the runtime maintains
const { relation: ChildOf } = Descriptor.Hierarchy(
  "Arena/ChildOf",
  "Arena/Children"
)

const Game = Schema.bind(
  Schema.fragment({
    components: { Position, Hand },
    relations: { ChildOf } // [!code highlight]
  })
)

const Arm = Game.System(
  "Arena/Arm",
  {
    commands: Game.System.commands(
      Game.System.spawns(Position, Hand),
      Game.System.relates(ChildOf)
    )
  },
  ({ commands }) => {
    const hand = commands.spawn(
      Game.Command.spawn([Position, { x: 0, y: 0 }], [Hand, {}])
    )

    // The sword is spawned already in the hand
    commands.spawn(
      Game.Command.relate(
        Game.Command.spawn([Position, { x: 4, y: 0 }]),
        ChildOf,
        hand
      ) // [!code highlight]
    )
  }
)
```

</Claim>

<Claim title="A missing parent is a value, not a crash">

Following an edge returns a `Result`, because the parent may be gone by
the time a system asks. A link the runtime refuses, such as an entity
parented to itself or a cycle, becomes a typed failure any system can read.

```ts twoslash title="follow.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const { relation: ChildOf } = Descriptor.Hierarchy("Arena/ChildOf", "Arena/Children")
const Game = Schema.bind(Schema.fragment({ components: { Position }, relations: { ChildOf } }))
// ---cut---
const Follow = Game.System(
  "Arena/Follow",
  {
    queries: {
      held: Game.Query({
        selection: { position: Game.Query.read(Position) },
        withRelations: [ChildOf]
      })
    },
    relationFailures: { childOf: Game.System.readRelationFailures(ChildOf) }
  },
  ({ queries, lookup, relationFailures }) => {
    for (const item of queries.held.each()) {
      const hand = lookup.parent(item.entity.id, ChildOf)
      if (!hand.ok) {
        const missing = hand.error._tag
        //    ^?
        continue
      }
      // hand.value is the parent's id: read it through a declared query
    }

    for (const failure of relationFailures.childOf.all()) {
      const refused = failure.error._tag
      //    ^?
    }
  }
)
```

</Claim>

<Claim title="An archer hears once that its target fell">

`Descriptor.Relation` is a plain edge with a reverse lookup and no tree.
Despawning the target clears the edge, and each cleared edge is a record
every reader sees once. The archer stands down at that moment, without
checking its target every tick.

```ts twoslash title="stand-down.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Idle = Descriptor.Tag("Arena/Idle")
// ---cut---
const { relation: Targeting } = Descriptor.Relation(
  "Arena/Targeting",
  "Arena/TargetedBy"
)

const Game = Schema.bind(
  Schema.fragment({ components: { Idle }, relations: { Targeting } })
)

const StandDown = Game.System(
  "Arena/StandDown",
  {
    droppedRelations: {
      lost: Game.System.readDroppedRelations(Targeting) // [!code highlight]
    },
    commands: Game.System.commands(Game.System.inserts(Idle))
  },
  ({ droppedRelations, commands }) => {
    for (const { source } of droppedRelations.lost.all()) {
      commands.insert(source, [Idle, {}])
    }
  }
)
```

</Claim>

<Claim title="Rewound and replayed with everything else">

Components and relation edges are part of the world's snapshot. A rollback
rewinds them with the rest of the world, and a replay applies the same
changes at the same point of every tick, on every machine.

</Claim>
