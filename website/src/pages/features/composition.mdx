A villager catches fire. A sword is put in a hand. An archer's target
falls. What an entity holds, and what it is linked to, changes all game
long, and Ritmo keeps each change safe to reason about.

<Game id="composition" ratio="16 / 9" />

`Burning` and `Wet` are components. Each rule is one system, and it acts
only on the villagers that hold what its query asks for.

<Claim title="A system adds only what its spec names">

The spark is a `Burning` component, inserted by a command. The spec lists
the components a system may insert or remove; any other insert does not
compile.

```ts twoslash title="ignite.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"

const Villager = Descriptor.Tag("Village/Villager")
const Burning = Descriptor.Tag("Village/Burning")
const Wet = Descriptor.Tag("Village/Wet")
const Spark = Descriptor.Event<{}>()("Village/Spark")

const Game = Schema.bind(Schema.fragment({ components: { Villager, Burning, Wet }, events: { Spark } }))
// ---cut---
// @errors: 2345
const Ignite = Game.System(
  "Village/Ignite",
  {
    queries: {
      dry: Game.Query({ selection: {}, with: [Villager], without: [Burning] })
    },
    events: { sparks: Game.System.readEvent(Spark) },

    // The only component this system may add
    commands: Game.System.commands(Game.System.inserts(Burning)) // [!code highlight]
  },

  ({ queries, events, commands }) => {
    if (events.sparks.all().length === 0) return
    for (const match of queries.dry.each()) {
      commands.insert(match.entity, [Burning, {}])

      // Not declared, so it does not compile
      commands.insert(match.entity, [Wet, {}])
    }
  }
)
```

Removing works the same way: `Game.System.removes(Burning)` in the spec,
`commands.remove(match.entity, Burning)` in the body. That is all `Douse`
does.

</Claim>

<Claim title="No loop sees an entity change shape under it">

Inserts, removes, spawns, and despawns wait for the next `applyDeferred()`
and land there together. The first villager in the demo, tick by tick: on
the spark's tick it still strolls, and from the next one `Panic` runs it.

```text title="the first villager, from the demo's world in Node"
tick 89  x 84.4  Villager, Position, Velocity
tick 90  x 84.9  Villager, Position, Velocity, Burning
tick 91  x 86.1  Villager, Position, Velocity, Burning
tick 92  x 87.3  Villager, Position, Velocity, Burning
```

```ts twoslash title="update.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Village/Position")
const Velocity = Descriptor.Component<{ x: number; y: number }>()("Village/Velocity")
const Burning = Descriptor.Tag("Village/Burning")
const Game = Schema.bind(Schema.fragment({ components: { Position, Velocity, Burning } }))
const Ignite = Game.System("Village/Ignite", { commands: Game.System.commands(Game.System.inserts(Burning)) }, () => {})
const Panic = Game.System("Village/Panic", {}, () => {})
// ---cut---
const Wander = Game.System(
  "Village/Wander",
  {
    queries: {
      strolling: Game.Query({
        selection: {
          position: Game.Query.write(Position),
          velocity: Game.Query.read(Velocity)
        },
        without: [Burning] // [!code highlight]
      })
    }
  },
  ({ queries }) => {
    for (const { data } of queries.strolling.each()) {
      const { x, y } = data.position.get()
      const velocity = data.velocity.get()
      data.position.set({ x: x + velocity.x, y: y + velocity.y })
    }
  }
)

// Burning lands at applyDeferred(): this tick the villager still
// strolls, the next Panic has it
const update = Game.Schedule(Ignite, Wander, Panic, Game.Schedule.applyDeferred())
```

</Claim>

<Claim title="Each system hears each change once">

`Game.Query.added(Burning)` matches the entities that gained the component
since this system last ran; `Game.System.readRemoved` lists the ones that
lost it. The demo counts every removal it hears: the first villager is
doused on tick 433, and counted once.

```text title="the first villager reaching the fountain"
tick 432  x 495.3  Villager, Position, Velocity, Burning  heard 8
tick 433  x 496.5  Villager, Position, Velocity, Wet  heard 9
tick 434  x 497.0  Villager, Position, Velocity, Wet  heard 10
tick 435  x 497.5  Villager, Position, Velocity, Wet  heard 10
```

`heard` counts the whole village, so tick 434 is a second villager doused
right behind the first.

```ts twoslash title="hiss.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Burning = Descriptor.Tag("Village/Burning")
const Game = Schema.bind(Schema.fragment({ components: { Burning } }))
// ---cut---
const Hiss = Game.System(
  "Village/Hiss",
  {
    queries: {
      lit: Game.Query({
        selection: {},
        with: [Burning],
        filters: [Game.Query.added(Burning)] // [!code highlight]
      })
    },
    removed: { doused: Game.System.readRemoved(Burning) } // [!code highlight]
  },
  ({ queries, removed }) => {
    for (const match of queries.lit.each()) {
      // play the whoosh at match.entity
    }
    for (const entityId of removed.doused.all()) {
      // play the hiss
    }
  }
)
```

</Claim>

<Claim title="A sword goes where its hand goes">

`Descriptor.Hierarchy` links a child to its parent. The runtime keeps the
reverse side (the knight's `Children`) in step, keeps children in order,
and despawns them with their parent.

```ts twoslash title="arm.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const Hand = Descriptor.Component<{}>()("Arena/Hand")
// ---cut---
// The edge, and the reverse side the runtime maintains
const { relation: ChildOf } = Descriptor.Hierarchy(
  "Arena/ChildOf",
  "Arena/Children"
)

const Game = Schema.bind(
  Schema.fragment({
    components: { Position, Hand },
    relations: { ChildOf } // [!code highlight]
  })
)

const Arm = Game.System(
  "Arena/Arm",
  {
    commands: Game.System.commands(
      Game.System.spawns(Position, Hand),
      Game.System.relates(ChildOf)
    )
  },
  ({ commands }) => {
    const hand = commands.spawn(
      Game.Command.spawn([Position, { x: 0, y: 0 }], [Hand, {}])
    )

    // The sword is spawned already in the hand
    commands.spawn(
      Game.Command.relate(
        Game.Command.spawn([Position, { x: 4, y: 0 }]),
        ChildOf,
        hand
      ) // [!code highlight]
    )
  }
)
```

</Claim>

<Claim title="A missing parent is a value, not a crash">

Following an edge returns a `Result`, because the parent may be gone by
the time a system asks. A link the runtime refuses, such as an entity
parented to itself or a cycle, becomes a typed failure any system can read.

```ts twoslash title="follow.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Position = Descriptor.Component<{ x: number; y: number }>()("Arena/Position")
const { relation: ChildOf } = Descriptor.Hierarchy("Arena/ChildOf", "Arena/Children")
const Game = Schema.bind(Schema.fragment({ components: { Position }, relations: { ChildOf } }))
// ---cut---
const Follow = Game.System(
  "Arena/Follow",
  {
    queries: {
      held: Game.Query({
        selection: { position: Game.Query.read(Position) },
        withRelations: [ChildOf]
      })
    },
    relationFailures: { childOf: Game.System.readRelationFailures(ChildOf) }
  },
  ({ queries, lookup, relationFailures }) => {
    for (const item of queries.held.each()) {
      const hand = lookup.parent(item.entity.id, ChildOf)
      if (!hand.ok) {
        const missing = hand.error._tag
        //    ^?
        continue
      }
      // hand.value is the parent's id: read it through a declared query
    }

    for (const failure of relationFailures.childOf.all()) {
      // A refused relate or unrelate, named:
      // "HierarchyCycle", "DuplicateChild", "MissingTargetEntity", ...
      const refused = failure.error._tag
    }
  }
)
```

</Claim>

<Claim title="An archer hears once that its target fell">

`Descriptor.Relation` is a plain edge with a reverse lookup and no tree.
Despawning the target clears the edge, and each cleared edge is a record
every reader sees once. The archer stands down at that moment, without
checking its target every tick.

```ts twoslash title="stand-down.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
const Idle = Descriptor.Tag("Arena/Idle")
// ---cut---
const { relation: Targeting } = Descriptor.Relation(
  "Arena/Targeting",
  "Arena/TargetedBy"
)

const Game = Schema.bind(
  Schema.fragment({ components: { Idle }, relations: { Targeting } })
)

const StandDown = Game.System(
  "Arena/StandDown",
  {
    droppedRelations: {
      lost: Game.System.readDroppedRelations(Targeting) // [!code highlight]
    },
    commands: Game.System.commands(Game.System.inserts(Idle))
  },
  ({ droppedRelations, commands }) => {
    for (const { source } of droppedRelations.lost.all()) {
      commands.insert(source, [Idle, {}])
    }
  }
)
```

</Claim>

<Claim title="Rewound and replayed with everything else">

Components and relation edges are part of the world's snapshot. A rollback
rewinds them with the rest of the world, and a replay applies the same
changes at the same point of every tick, on every machine.

</Claim>
