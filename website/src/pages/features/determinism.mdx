Run a game twice with the same input and you expect the same game. One call
to `Math.random()`, or one engine rounding `Math.sin` its own way, and the
two runs part. A Ritmo game plays the same, bit for bit, wherever it runs.

<Game id="determinism" ratio="16 / 9" />

Each side runs two copies of one world, drawn on top of each other: one
copy filled, the other as rings. On the left the gusts come from a seeded
`Random`, and the copies stay one picture. On the right one system calls
`Math.random()`, and they split at the first gust.

That is what the rest of Ritmo stands on: [replays](/features/replays/)
that play back from a few kilobytes of input, [online matches](/features/rollback/)
where every peer reaches the same world, and a bug from a player's phone
that reproduces on your laptop.

<Claim title="Same seed, same rolls, same math">

Runs drift apart in three places, and each has one replacement:

- **Time.** The simulation steps at a fixed rate (`Clock.hz(60)`) and reads
  time from its clock, not from when frames arrive.
- **Randomness.** Rolls come from a seeded generator kept in the world
  (`Random.draw`), so a replay draws them again.
- **Math.** `Ops` computes `sin`, `atan2`, `pow` and the rest with
  operations every engine rounds exactly.

In a system it is ordinary code with two different imports:

```ts twoslash title="gust.ts"
import { Descriptor, Ops, Random, Schema } from "@typeonce/ritmo"
const Rng = Descriptor.ConstructedResource(Random.codec)("Game/Rng")
const Wind = Descriptor.Resource<{ readonly x: number; readonly y: number }>()("Game/Wind")
const Game = Schema.bind(Schema.fragment({ resources: { Rng, Wind } }))
// ---cut---
const Gust = Game.System(
  "Game/Gust",
  {
    resources: {
      rng: Game.System.writeResource(Rng),
      wind: Game.System.writeResource(Wind)
    }
  },
  ({ resources }) => {
    // Seeded and kept in the world: a replay draws the same angle
    const angle = Random.draw(resources.rng).range(0, 2 * Math.PI)
    // The same bits on every engine, unlike Math.cos and Math.sin
    resources.wind.set({ x: Ops.cos(angle), y: Ops.sin(angle) })
  }
)
```

</Claim>

<Claim title="Drifting code is a lint error">

Lint rules catch simulation code that reaches for the drifting version,
and say what to use instead. `oxlint --fix` rewrites the call and adds the
import.

```text title="oxlint"
error ritmo(use-ops-for-math): Math.sin may return a different last bit on
another browser or CPU, and the simulation grows that bit into a different
run. Use `Ops.sin` from `@typeonce/ritmo` (`import { Ops } from
"@typeonce/ritmo"`), which returns the same bits everywhere. Math.sqrt,
abs, min, max, floor, ceil, round, trunc, and sign are exact everywhere and
stay as they are.
```

`Date.now`, timers, `Math.random`, and page APIs inside systems get the
same treatment. Dependencies are not linted: `ritmo-devtools scan <entry>`
lists the drifting calls in every package the simulation imports.

</Claim>

<Claim title="A test names the frame, the value, and the system">

`Determinism.check` plays the same script twice and compares every value
in the world after every frame.

```ts twoslash title="determinism.test.ts"
import { Descriptor, HostClock, Schema } from "@typeonce/ritmo"
import { Determinism } from "@typeonce/ritmo-devtools"
const Score = Descriptor.Resource<number>()("Game/Score")
const Game = Schema.bind(Schema.fragment({ resources: { Score } }))
const update = Game.Schedule()
const makeSimulation = (hostClock: HostClock.HostClock) => ({
  runtime: Game.Runtime.make({ services: Game.Runtime.services(), resources: { Score: 0 }, debug: { hostClock } }).value!,
  schedules: { update }
})
// ---cut---
const result = Determinism.check(
  ({ hostClock }) => makeSimulation(hostClock),
  {
    schedule: "update",
    frames: 1800, // thirty seconds
    hostClock: HostClock.test()
  }
)

if (!result.ok) {
  throw new Error(JSON.stringify(result))
}
```

Run on the demo's `Math.random()` world, it stops at the first gust:

```text title="Determinism.check, the drifting world"

  "frame": 60,
  "reason": "difference",

  "first": 51.05881906664952,
  "second": 51.049359557171876,
  "after": "Drift/UnseededGust",

```

The seeded world passes all 600 frames: `{ "ok": true, "frames": 600 }`.

</Claim>

<Claim title="Every browser checked, on every change">

`ritmo-devtools verify` plays a replay in Node, Chromium, WebKit, and
Firefox, and names the first tick and value they disagree on. Ritmo's own
CI runs it on every change, against a recorded online match.

```sh
ritmo-devtools verify replay/target.ts replay/match.json \
  --engines node,chromium,webkit,firefox
```

</Claim>

This is what [online multiplayer](/features/rollback/) needs from a game:
every machine taking the same inputs to the same world. To find the places
a game breaks it, see [Bugs found before players](/features/bugs/).
