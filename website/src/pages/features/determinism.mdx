## Where runs drift apart

JavaScript leaves room for two runs of the same code to differ, and a game
turns the smallest difference into a different game a few seconds later:

- **Time.** Frames arrive whenever the screen is ready. The simulation
  steps at a fixed rate instead (`Clock.hz(60)`), and reads time from its
  clock, never from the page.
- **Randomness.** `Math.random()` cannot be replayed. Rolls come from a
  seeded generator kept in the world (`Random.draw`), so the same seed draws
  the same rolls.
- **Math.** The standard lets engines round `Math.sin`, `cos`, `atan2`,
  `exp`, `pow` and the rest as they like, and they do: Chrome, Safari,
  Firefox, macOS, and Linux disagree in the last bit. `Ops` is a port of
  the same functions written only with operations every engine rounds
  exactly, so it returns the same bits everywhere.

The lint rules keep simulation code on that path, and say what to use
instead:

```text
error ritmo(use-ops-for-math): Math.sin may return a different last bit on
another browser or CPU, and the simulation grows that bit into a different
run. Use `Ops.sin` from `@typeonce/ritmo` (`import { Ops } from
"@typeonce/ritmo"`), which returns the same bits everywhere. Math.sqrt,
abs, min, max, floor, ceil, round, trunc, and sign are exact everywhere and
stay as they are.
```

`oxlint --fix` rewrites the call and adds the import. Rules for `Date.now`,
timers, `Math.random`, and page APIs inside systems work the same way.
Dependencies are not linted: `ritmo-devtools scan <entry>` lists the calls
in every package the simulation imports.

## Checking it

`Determinism.check` plays the same script twice and compares every value
in the world after every frame. A difference names the frame, the value,
and the system that wrote it first:

```ts twoslash title="determinism.test.ts"
import { Descriptor, HostClock, Schema } from "@typeonce/ritmo"
import { Determinism } from "@typeonce/ritmo-devtools"
const Score = Descriptor.Resource<number>()("Game/Score")
const Game = Schema.bind(Schema.fragment({ resources: { Score } }))
const update = Game.Schedule()
const makeSimulation = (hostClock: HostClock.HostClock) => ({
  runtime: Game.Runtime.make({ services: Game.Runtime.services(), resources: { Score: 0 }, debug: { hostClock } }).value!,
  schedules: { update }
})
// ---cut---
const result = Determinism.check(
  ({ hostClock }) => makeSimulation(hostClock),
  {
    schedule: "update",
    frames: 1800, // thirty seconds
    hostClock: HostClock.test()
  }
)

if (!result.ok) {
  throw new Error(JSON.stringify(result))
}
```

Across engines, `ritmo-devtools verify` plays a replay in Node, Chromium,
WebKit, and Firefox and names the first tick and value they disagree on.
Ritmo's own CI runs it on every change, on a recorded online match:

```sh
ritmo-devtools verify replay/target.ts replay/match.json --engines node,chromium,webkit,firefox
```

## What it buys

- [Replays](/features/replays/) that play back exactly, from a few
  kilobytes of input.
- Headless tests that mean something: a run in Node is the run a player
  sees.
- A bug report from a player's phone that reproduces on a laptop.

It is also what online play built on lockstep or rollback needs from a
game: every machine running the same inputs to the same world. A game
built on Ritmo has that part already, and
[`@typeonce/ritmo-netcode`](/features/rollback/) runs it online.
