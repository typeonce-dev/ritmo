Two players on one keyboard, four more on gamepads, one screen. Each player
joins by pressing a button on a free device, and your game reads each one
on their own.

<Game id="town" ratio="3 / 2" />

Player one walks with the arrows. For a second player, press any key on
WASD, or any button on a gamepad, and they appear next to you. Q (or Ⓑ)
leaves.

## What you get

- Players are named slots. A press on a free device joins the first free
  slot, and that press does nothing else.
- Each slot reports its own actions, the device it holds, and when someone
  joins or leaves.
- A slot the game does not have is a compile error, not an `undefined` at
  run time.
- An unplugged pad keeps its seat, and the player is back when it
  reconnects.
- The whole room is one input source, so it replays and fuzzes like a
  single player.

A single player on many devices is a merge (see
[Every device, one player](/features/devices/)). Several players is a
**pool**: each device belongs to whoever joined with it.

## Players are slots

Your game names its slots. A device nobody holds joins the first free slot
when someone presses a button on it. That press does nothing else, so
joining never also jumps.

```ts twoslash title="players.ts"
import { Controls, Gamepad, Keyboard } from "@typeonce/ritmo-browser"
// ---cut---
const Actions = Controls.actions({
  buttons: ["talk", "back"],
  vectors: ["move"]
})

// [!code highlight:5]
const Players = Controls.players(Actions, {
  slots: ["p1", "p2"],
  join: "any",
  leave: "back"
})

const wasd = {
  move: Keyboard.vector({ up: ["w"], down: ["s"], left: ["a"], right: ["d"] }),
  talk: [" "],
  back: ["q"]
} as const

const arrows = {
  move: Keyboard.vector({
    up: ["ArrowUp"],
    down: ["ArrowDown"],
    left: ["ArrowLeft"],
    right: ["ArrowRight"]
  }),
  talk: ["Enter"],
  back: ["Backspace"]
} as const

const pad = {
  move: Gamepad.vector({ stick: "left" }),
  talk: ["south"],
  back: ["east"]
} as const

const players = Players.pool({
  // Two players on one keyboard
  left: Keyboard.actions(window, wasd),
  right: Keyboard.actions(window, arrows),

  // Every pad on its own
  pads: Gamepad.pads(window, pad, 4)
})
```

Each slot has its own actions, and tells the game when someone arrives or
goes:

```ts twoslash title="players.ts"
import { Controls, Gamepad, Keyboard } from "@typeonce/ritmo-browser"
const Actions = Controls.actions({ buttons: ["talk", "back"], vectors: ["move"] })
const Players = Controls.players(Actions, { slots: ["p1", "p2"], join: "any", leave: "back" })
const wasd = { move: Keyboard.vector({ up: ["w"], down: ["s"], left: ["a"], right: ["d"] }), talk: [" "], back: ["q"] } as const
const arrows = { move: Keyboard.vector({ up: ["ArrowUp"], down: ["ArrowDown"], left: ["ArrowLeft"], right: ["ArrowRight"] }), talk: ["Enter"], back: ["Backspace"] } as const
const pad = { move: Gamepad.vector({ stick: "left" }), talk: ["south"], back: ["east"] } as const
const players = Players.pool({ left: Keyboard.actions(window, wasd), right: Keyboard.actions(window, arrows), pads: Gamepad.pads(window, pad, 4) })
declare const input: ReturnType<typeof players.snapshot>
declare const spawnSecondPlayer: () => void
// ---cut---
// In a system: input = resources.input.get()
if (input.p2.event === "joined") {
  spawnSecondPlayer()
}

const walk = input.p2.vectors.move

if (input.p2.joined && input.p2.device === "pads") {
  // false while the pad is unplugged: the seat is kept
  const connected = input.p2.connected
}
```

There are two slots, so a third player is an error, not an `undefined` at
run time:

```ts twoslash title="players.ts"
import { Controls, Gamepad, Keyboard } from "@typeonce/ritmo-browser"
const Actions = Controls.actions({ buttons: ["talk", "back"], vectors: ["move"] })
const Players = Controls.players(Actions, { slots: ["p1", "p2"], join: "any", leave: "back" })
const pad = { move: Gamepad.vector({ stick: "left" }), talk: ["south"], back: ["east"] } as const
const players = Players.pool({ pads: Gamepad.pads(window, pad, 4) })
declare const input: ReturnType<typeof players.snapshot>
// ---cut---
// @errors: 2339
input.p3.actions.talk
```

## What the pool takes care of

- **Joining and leaving.** Joining is open when the game says so
  (`setJoining`), once for drop-in play or only on a join screen. A pause
  menu frees a slot with `leave("p2")`.
- **Seats from the start.** A player who is in before anyone presses
  anything is seated by the game: `seat("p1", "right")`, or the first pad
  with `seat("p1", { pads: 0 })`. A taken seat comes back as a reason, not
  a crash.
- **Unplugged pads.** A pad that disconnects keeps its slot, and the player
  is back in the moment it reconnects.
- **Touch and rebinding** work as they do for one player: the town seats
  player one on on-screen buttons on a phone.

## Every player is in the replay

The pool is one source: one `snapshot()` reads every pooled device and
decides the joins across them. Declare it with `InputCapture.SourceOf`, as
for one player, and a replay or the fuzzer provides the whole room at once.

```ts twoslash title="input.ts"
import { Controls, Gamepad, Keyboard } from "@typeonce/ritmo-browser"
const Actions = Controls.actions({ buttons: ["talk", "back"], vectors: ["move"] })
const Players = Controls.players(Actions, { slots: ["p1", "p2"], join: "any", leave: "back" })
const pad = { move: Gamepad.vector({ stick: "left" }), talk: ["south"], back: ["east"] } as const
const players = Players.pool({ pads: Gamepad.pads(window, pad, 4) })
// ---cut---
import { Descriptor } from "@typeonce/ritmo"
import { InputCapture } from "@typeonce/ritmo-browser"

const PlayersInput = Descriptor.Service<
  InputCapture.SourceOf<typeof players> // [!code highlight]
>()("Game/Players")
```

Opening and closing the join, seating, and leaving are calls on the pool
itself, so make them from the host, not from a system. The game stays
replayable, and every part of it is tested headless with scripted keyboards
and pads (`Gamepad.scriptedPads`), with no controller in reach.

## Playing over the network

A pool is everyone on one machine. For players on different machines,
Ritmo runs [online multiplayer with rollback](/features/rollback/): each
peer owns a seat, and every peer runs the same ticks. The setup for local
play in full is in
[Loop, input, rendering](/docs/browser/#local-multiplayer).
