A player wants dash on J, or on the other face button. Your game only ever
reads actions, so rebinding swaps what is under them and no rule changes.

<Game id="rebind" />

Open **Controls** in the corner, click a binding, and press the new key or
pad button. Reload the page: your bindings are still there.

## What you get

- One call per device swaps its bindings. Systems keep reading the same
  actions.
- A settings screen can wait for "press a key" and bind whatever comes
  next, bound or not.
- Saved bindings are checked against your actions when they load. A stale
  or hand-edited file comes back as a reason, never a broken pad.
- A binding to an action or button that does not exist does not compile.
- [Replays](/features/replays/) record actions, not keys, so a rebind never
  changes how a replay plays back.

## One call

Every keyboard, gamepad, and pointer source has `rebind`. The actions stay
the same, so no system changes.

```ts twoslash title="settings.ts"
import { Gamepad, Keyboard } from "@typeonce/ritmo-browser"
const keys = { move: Keyboard.vector({ up: ["w"], down: ["s"], left: ["a"], right: ["d"] }), dash: [" "], pause: ["Escape"] } as const
const pad = { move: Gamepad.vector({ stick: "left" }), dash: ["south"], pause: ["start"] } as const
declare const keyboard: Keyboard.Actions<typeof keys>
declare const gamepad: Gamepad.Actions<typeof pad>
// ---cut---
// Dash moves to J on the keyboard...
keyboard.rebind({ ...keys, dash: ["j"] })

// ...and to the west button on the pad (X on Xbox, Square on PlayStation)
gamepad.rebind({ ...pad, dash: ["west"] })
```

A merge exposes each device's `rebind` by name, for a settings screen over
the whole thing: `controls.rebind.keyboard(...)`.

## Waiting for the new button

A settings screen asks "press a key" and binds whatever comes next.
`Keyboard.presses` reports every key that goes down, bound or not, and the
pad's snapshot names every button, whatever the bindings.

```ts twoslash title="settings.ts"
import { Gamepad, Keyboard } from "@typeonce/ritmo-browser"
const keys = { move: Keyboard.vector({ up: ["w"], down: ["s"], left: ["a"], right: ["d"] }), dash: [" "], pause: ["Escape"] } as const
const pad = { move: Gamepad.vector({ stick: "left" }), dash: ["south"], pause: ["start"] } as const
declare const keyboard: Keyboard.Actions<typeof keys>
declare const gamepad: Gamepad.Actions<typeof pad>
declare const snapshot: Gamepad.Snapshot<typeof pad>
// ---cut---
const presses = Keyboard.presses(window)

// Each frame while the screen waits for the new dash key:
const press = presses.snapshot()[0]

if (press !== undefined) {
  keyboard.rebind({ ...keys, dash: [press.key] })
}

// And for the pad, the first button pressed:
const button = Gamepad.buttonNames.find((name) => snapshot.buttons[name].pressed)
//    ^?
```

## Saved bindings are checked on the way back

Bindings are plain data: save them as JSON wherever the game keeps its
settings. On the next visit `parseRebinding` checks them against the
game's actions before they are used. A file from an older version, or one
edited by hand, comes back as a reason, not a broken pad:

```ts twoslash title="settings.ts"
import { Gamepad } from "@typeonce/ritmo-browser"
const pad = { move: Gamepad.vector({ stick: "left" }), dash: ["south"], pause: ["start"] } as const
declare const gamepad: Gamepad.Actions<typeof pad>
declare const stored: string
// ---cut---
const saved = Gamepad.parseRebinding(pad, JSON.parse(stored))

if (saved.ok) {
  gamepad.rebind(saved.value)
} else {
  // Keep the defaults
  console.warn(saved.error.message)
}
```

```text
{
  _tag: "InvalidRebinding",
  path: "dash[0]",
  message: "expected one of south, east, west, north, leftBumper, ..."

```

## Mistakes in code do not compile

A binding for an action the game does not have, or a button no pad has, is
an error in the editor:

```ts twoslash title="settings.ts"
import { Gamepad } from "@typeonce/ritmo-browser"
const pad = { move: Gamepad.vector({ stick: "left" }), dash: ["south"], pause: ["start"] } as const
declare const gamepad: Gamepad.Actions<typeof pad>
// ---cut---
// @errors: 2322
// The game has no "jump" action
gamepad.rebind({ ...pad, jump: ["north"] })

// Buttons are named by place: "south", not "A"
gamepad.rebind({ ...pad, dash: ["A"] })
```

## Small things done right

- A key held while it is rebound does not fire the action it now belongs
  to until it is pressed again, so an action never turns on without a
  press.
- Buttons are named by where they sit on the pad, so a binding saved with
  an Xbox pad works on a PlayStation or a Nintendo one.
- Touch controls have no `rebind`: on a touch screen the layout is the
  binding.

Rebinding works on every device a merge holds: see
[Every device, one player](/features/devices/). How a settings screen fits
into the loop is in [Loop, input, rendering](/docs/browser/#input).
