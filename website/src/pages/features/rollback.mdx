In an online match, every peer runs the same simulation on its own machine,
and the peers send each other only their input. Nobody waits for it: each
peer guesses the input that has not arrived yet, and when the real input
turns out different, it rolls back to the tick it was for and runs again up
to now.

<Game id="rollback" ratio="10 / 11" />

Both views above are peers of one match, each with its own runtime, talking
over a fake network with the latency picked in the corner. Your moves reach
the other peer late, so it rolls back and runs the ticks again; the HUD under
each view counts the rollbacks, and up to which tick the two agree.

## Online multiplayer

`@typeonce/ritmo-netcode` gives every peer a session. The session exchanges
inputs, takes the checkpoints, rolls back, and keeps the peers in step. The
game gives it three things: where input comes from, the simulation, and a
connection.

### 1. Input comes from one source

The simulation never sees the network. It reads every seat's input for the
tick from one source, captured like any other input, and the session fills
that source before each tick. The input's schema is the game's own (Effect's
here; any Standard Schema works), and input from other peers is decoded with
it as it arrives.

```ts twoslash title="input.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
import { InputCapture } from "@typeonce/ritmo-browser"
import { Netcode } from "@typeonce/ritmo-netcode"
// ---cut---
const PlayerInput = S.Struct({ dx: S.Literals([-1, 0, 1]), fire: S.Boolean })
type PlayerInput = typeof PlayerInput.Type

// Every seat's input for the tick being run.
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats") // [!code highlight]
const Inputs =
  Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()(
    "Game/Inputs"
  )

const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, {
  name: "Game/Capture",
  source: Seats,
  resource: Inputs
})

// The schedule every peer ticks the same way.
const simulate = Game.Schedule(Capture /* , Move, Fire, ... */)

// Two seats. Input from another peer is decoded with the schema.
const seats = Netcode.seats(codec(PlayerInput), {
  count: 2,
  idle: { dx: 0, fire: false }
}) // [!code highlight]
if (!seats.ok) throw new Error(seats.error.reason)

const runtime = Game.Runtime.make({
  services: Game.Runtime.services(
    Game.Runtime.service(Seats, seats.value.source)
  ), // [!code highlight]
  resources: { Inputs: [] }
}).value
```

Remote input never goes through `runtime.send`: after a rollback, the
simulation would read it on the wrong tick.

### 2. A session per peer

Each peer makes a session around its runtime. There are two, for two kinds
of game:

- `Netcode.rollback` runs every tick at once, guessing input that has not arrived. For real-time games: input feels immediate.
- `Netcode.lockstep` waits for every seat's input. For turn-based games: nothing ever runs twice.

```ts twoslash title="session.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"
import { BrowserHostClock, InputCapture } from "@typeonce/ritmo-browser"
import { Netcode, WebSocketNetworkLink } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats")
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })
const simulate = Game.Schedule(Capture)
declare const seats: Netcode.Seats<PlayerInput>
const runtime = Game.Runtime.make({ services: Game.Runtime.services(Game.Runtime.service(Seats, seats.source)), resources: { Inputs: [] } }).value
const step = Clock.hz(60)
// ---cut---
// A WebSocket the game opened, to a relay that forwards to the other peers.
const socket = new WebSocket("wss://relay.example.com/match/42")

const session = Netcode.rollback(runtime, {
  simulate,
  seats,
  seat: 1, // seat 0 hosts: every peer starts from its world
  links: [WebSocketNetworkLink.make(socket)], // [!code highlight]
  hostClock: BrowserHostClock.make(window),
  step
})
if (!session.ok) throw new Error(session.error.reason)
```

Ritmo carries no server and opens no connection. A link wraps one the game
already opened, so where to connect and when to retry stay with the game:

- `WebSocketNetworkLink`: a relay, from the browser, Node, Deno, or Bun.
- `WebRtcNetworkLink`: a data channel, straight between peers.
- Anything else: implement `send`, `receive`, and `status`.

Each input is for a tick a little ahead of the one it is pressed on
(`inputDelay`, 2 ticks by default). The lag is too short to feel, and it
gives the input time to reach the other peers before its tick runs.

Give `adaptiveDelay: { min: 1, max: 4 }` instead and the session moves the
delay with the measured round trip. Each peer moves only its own: every
input says which tick it is for, so the peers never have to agree on a
change.

### 3. The loop drives it

The session plugs into the fixed-step loop. On each step it reads the
network, rolls back if a guess was wrong, ticks the simulation, and sends
this peer's input to the others.

```ts twoslash title="loop.ts"
import { Clock, FixedLoop } from "@typeonce/ritmo"
import { BrowserTickSource } from "@typeonce/ritmo-browser"
import type { Netcode } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
declare const session: Netcode.Session<PlayerInput, never>
declare const readInput: () => PlayerInput
declare const draw: () => void
declare const showDisconnected: (failure: unknown) => void
const step = Clock.hz(60)
// ---cut---
FixedLoop.start({
  source: BrowserTickSource.make(window),
  step,
  maxFrameSeconds: 0.25,
  maxStepsPerFrame: 5,

  // Slows this peer while it runs ahead of the others.
  rate: session.rate, // [!code highlight]

  // Advances the session with this seat's input, once per step.
  update: session.update({ // [!code highlight]
    input: readInput,
    // A desync is a bug in the game: log it. The session resyncs on its own.
    onHalted: (error) => console.error(error)
  }),

  // Drawing runs outside the simulation, so it never rolls back.
  render: draw,

  // The session ended: a peer left, or runs another version.
  onFailure: showDisconnected
})
```

## Hidden tabs

A browser stops a hidden tab's frames, so that peer goes silent, and after
`timeoutMS` the others would end the match. Given the tab's visibility, a
session tells the others the moment it hides, and they apply a policy
instead: wait for it (`"stall"`), or play on with idle input for it and
resync it when it returns (`"resync-on-return"`).

```ts twoslash title="hidden.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"
import { BrowserHostClock, BrowserVisibility, InputCapture } from "@typeonce/ritmo-browser"
import { Netcode, WebSocketNetworkLink } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats")
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })
const simulate = Game.Schedule(Capture)
declare const seats: Netcode.Seats<PlayerInput>
const runtime = Game.Runtime.make({ services: Game.Runtime.services(Game.Runtime.service(Seats, seats.source)), resources: { Inputs: [] } }).value
const step = Clock.hz(60)
declare const socket: WebSocket
declare const names: ReadonlyArray<string>
// ---cut---
const session = Netcode.rollback(runtime, {
  simulate,
  seats,
  seat: 1,
  links: [WebSocketNetworkLink.make(socket)],
  hostClock: BrowserHostClock.make(window),
  step,
  hidden: {
    // [!code highlight]
    visibility: BrowserVisibility.make(document), // [!code highlight]
    // A tab closed while hidden still ends the match, 30 s + timeoutMS later
    afterMS: 30_000,
    then: "resync-on-return" // [!code highlight]
  }
})
if (!session.ok) throw new Error(session.error.reason)

// In the HUD: who everyone is waiting for.
const away = session.value
  .status()
  .hidden.flatMap((hidden, seat) => (hidden ? [names[seat]] : []))
```

## What cannot work does not compile

A rollback runs ticks again, so whatever they call runs again: a sound would
play once per rollback, and state a system keeps in `local` would not come
back. The session checks the simulation for both, its state transitions
included:

```ts twoslash
import { Clock, Descriptor, HostClock, Schema } from "@typeonce/ritmo"
import { InputCapture } from "@typeonce/ritmo-browser"
import { Netcode, type NetworkLink } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats")
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })
declare const seats: Netcode.Seats<PlayerInput>
declare const link: NetworkLink.NetworkLink
const runtime = Game.Runtime.make({ services: Game.Runtime.services(Game.Runtime.service(Seats, seats.source)), resources: { Inputs: [] } }).value
const options = { seats, seat: 0, links: [link], hostClock: HostClock.standard, step: Clock.hz(60) }
// ---cut---
const Combo = Game.System("Game/Combo", { local: () => ({ hits: 0 }) }, ({ local }) => {
  local.hits++
})

// @errors: 2375
Netcode.rollback(runtime, { ...options, simulate: Game.Schedule(Capture, Combo) })
```

A runtime that cannot save, and a simulation whose services the runtime does
not provide, do not compile either.

## A physics library rolls back too

A library that keeps its own world, like a physics engine, is a service made
with `Checkpoint.rewindable`: every checkpoint saves it, and every rollback
restores it. Systems read its `current` value each tick:

```ts twoslash
import { Checkpoint, Descriptor, Result, Schema } from "@typeonce/ritmo"
declare class PhysicsWorld {
  step(): void
  takeSnapshot(): Uint8Array
  static restoreSnapshot(bytes: Uint8Array): PhysicsWorld | undefined
}
declare const world: PhysicsWorld
const Game = Schema.bind(Schema.fragment({}))
// ---cut---
const physics = Checkpoint.rewindable(world, {
  save: (world) => world.takeSnapshot(),
  restore: (bytes) => {
    const restored = PhysicsWorld.restoreSnapshot(bytes)
    return restored === undefined
      ? Result.failure({ _tag: "CorruptSnapshot" as const })
      : Result.success(restored)
  }
})
const Physics = Descriptor.Service<typeof physics>()("Game/Physics")

const Step = Game.System(
  "Game/Step",
  { services: { physics: Game.System.service(Physics) } },
  ({ services }) => {
    services.physics.current.step()
  }
)
```

Saves and checksums see only the world, so copy what gameplay reads from the
library (positions, contacts) into components each tick: that is what peers
compare, and what a resync restores.

## Peers agree, or say so

Every 30 ticks, the peers compare a checksum of a tick that every seat's real
input has reached. A mismatch means the game is not deterministic somewhere:
the session stops with `Desynced`, and a resync starts every peer again from
seat 0's world. `status()` says how far they agree, for a HUD or a test:

```ts twoslash
import type { Netcode } from "@typeonce/ritmo-netcode"
declare const session: Netcode.Session<unknown, never>
// ---cut---
const { tick, confirmed, verified, rollbacks } = session.status()
```

A desync in a live match is the last place to find one. A
[sync test](/features/bugs/#rollback-checked-on-every-tick) catches it in a
test run, on the tick it starts.

## Sounds play once

A tick run again publishes its events again, so a sound played from an event
would play once per run. The session hands the host each event of the
simulation in three streams: `confirmed` once its tick can no longer change,
`predicted` while it still may, and `withdrawn` for the ticks a rollback
undid.

```ts twoslash
import { Descriptor } from "@typeonce/ritmo"
import type { Netcode } from "@typeonce/ritmo-netcode"
const Hit = Descriptor.Event<{ readonly kind: "body" | "shield"; readonly x: number }>()("Game/Hit")
declare const session: Netcode.Session<unknown, never, typeof Hit>
declare const sounds: { readonly play: (kind: "body" | "shield") => void }
declare const particles: { readonly burst: (tick: number, x: number) => void; readonly cancel: (tick: number) => void }
// ---cut---
const hits = session.events(Hit) // one reader for each place that acts on hits

// Every frame, after the session advanced:
for (const { tick } of hits.withdrawn()) particles.cancel(tick) // a rollback undid it
// At once, and cancelled if a rollback undoes it
for (const { tick, value } of hits.predicted()) particles.burst(tick, value.x)
for (const { value } of hits.confirmed()) sounds.play(value.kind) // exactly once
```

A tick that runs again with the same hits keeps its particles: only hits
that changed are withdrawn and predicted again.

## Under the hood: checkpoints

A session rolls back with the runtime's own checkpoints, which a game can also
use directly, for an undo say. `runtime.checkpoint(simulate)` marks the world
between ticks, and `runtime.rewind(checkpoint)` puts it back: ticking again
gives the same results, bit for bit, as a runtime that never went back.

```ts twoslash title="rollback.ts"
import { Checkpoint, Descriptor, Schema } from "@typeonce/ritmo"
const Root = Schema.defineRoot("Game")
const Score = Descriptor.Resource<number>()("Game/Score")
const Game = Schema.bind(Schema.fragment({ resources: { Score } }), Root)
const simulate = Game.Schedule()
const runtime = Game.Runtime.make({ services: Game.Runtime.services(), resources: { Score: 0 } }).value!
declare const wrongTick: number
// ---cut---
const history = new Map<number, Checkpoint.Checkpoint<typeof Root>>()

// Before each tick: keep where it starts.
history.set(0, runtime.checkpoint(simulate)) // [!code highlight]
runtime.tick(simulate)

// Later: go back, and run again from there.
const rewound = runtime.rewind(history.get(wrongTick)!) // [!code highlight]
if (!rewound.ok) console.error(rewound.error) // older than the checkpoints kept
```

A checkpoint copies almost nothing when it is taken. The first change to a
page of values, an entity, or a relation keeps what it replaced, so a tick
costs what it changes, not what the world holds.

## The screen sees one change

Rendering runs outside the simulation, so it never goes back. It sees a
rollback like any other tick: a value that moved, an entity that is gone, one
that appeared. A shot the rollback took away and brought back is just a shot
that moved, so its sprite stays where it is instead of being destroyed and
made again.
