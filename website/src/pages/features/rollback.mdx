Online, the other player's input always arrives late, and waiting for it
makes every press lag. With rollback, each peer guesses the missing input
and plays on. When the real input turns out different, it rewinds to that
tick and runs forward again, within one frame.

<Game id="rollback" ratio="10 / 11" />

Both views are peers of one match over a fake network. Raise the latency in
the corner and keep moving: each HUD counts rollbacks and shows up to which
tick the peers agree.

## What you get

- Input that feels immediate, and every peer reaching the same world.
- Your transport: WebSocket, WebRTC, or anything that sends bytes.
- One simulation for offline, tests, and online: it never sees the network.
- Code a rollback would break does not compile.
- Checksums that catch a desync on its tick, then repair it.

## The simulation reads one input

The simulation never sees the network. It reads every seat's input for the
tick from one source, and the session fills it before each tick. The input
schema is the game's own (Effect here, any Standard Schema works), and input
from other peers is decoded with it.

```ts twoslash title="input.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
import { InputCapture } from "@typeonce/ritmo-browser"
import { Netcode } from "@typeonce/ritmo-netcode"
const PlayerInput = S.Struct({ dx: S.Literals([-1, 0, 1]), fire: S.Boolean })
type PlayerInput = typeof PlayerInput.Type
const Inputs =
  Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()(
    "Game/Inputs"
  )
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
// ---cut---
// Every seat's input for the tick being run
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats") // [!code highlight]

// Two seats; input from another peer is decoded with the schema
const seats = Netcode.seats(codec(PlayerInput), {
  count: 2,
  idle: { dx: 0, fire: false }
})
if (!seats.ok) throw new Error(seats.error.reason)

const runtime = Game.Runtime.make({
  services: Game.Runtime.services(
    Game.Runtime.service(Seats, seats.value.source) // [!code highlight]
  ),
  resources: { Inputs: [] }
}).value
```

`InputCapture.system` copies the source into `Inputs` each tick, so systems
read it like any captured input. Remote input never goes through
`runtime.send`: after a rollback, it would land on the wrong tick.

## One session per peer, over your connection

Each peer wraps its runtime in a session: `Netcode.rollback` for real-time
games, or `Netcode.lockstep`, which waits for every seat's input, for
turn-based ones.

```ts twoslash title="session.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"
import { BrowserHostClock, InputCapture } from "@typeonce/ritmo-browser"
import { Netcode, WebSocketNetworkLink } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats")
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })
const simulate = Game.Schedule(Capture)
declare const seats: Netcode.Seats<PlayerInput>
const runtime = Game.Runtime.make({ services: Game.Runtime.services(Game.Runtime.service(Seats, seats.source)), resources: { Inputs: [] } }).value
const step = Clock.hz(60)
// ---cut---
// A socket the game opened, to a relay between the peers
const socket = new WebSocket("wss://relay.example.com/match/42")

const session = Netcode.rollback(runtime, {
  simulate,
  seats,
  seat: 1, // seat 0 hosts: every peer starts from its world
  links: [WebSocketNetworkLink.make(socket)], // [!code highlight]
  hostClock: BrowserHostClock.make(window),
  step
})
```

Ritmo runs no server and opens no connection. A link wraps one your game
opened: `WebSocketNetworkLink` for a relay, `WebRtcNetworkLink` for a data channel
straight between peers, or your own `send`, `receive`, and `status`.

Each input is for a tick slightly ahead (2 by default): too short to feel,
long enough to arrive in time. `adaptiveDelay` follows the round trip.

## The loop drives it

Each step of the fixed-step loop, the session reads the network, rolls back
if a guess was wrong, ticks, and sends this peer's input.

```ts twoslash title="loop.ts"
import { Clock, FixedLoop } from "@typeonce/ritmo"
import { BrowserTickSource } from "@typeonce/ritmo-browser"
import type { Netcode } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
declare const session: Netcode.Session<PlayerInput, never>
declare const readInput: () => PlayerInput
declare const draw: () => void
declare const showDisconnected: (failure: unknown) => void
const step = Clock.hz(60)
// ---cut---
FixedLoop.start({
  source: BrowserTickSource.make(window),
  step,
  maxFrameSeconds: 0.25,
  maxStepsPerFrame: 5,
  rate: session.rate, // slows this peer while it runs ahead
  update: session.update({ // [!code highlight]
    input: readInput,
    // A desync is a bug in the game: log it. The session resyncs.
    onHalted: (error) => console.error(error)
  }),
  render: draw, // outside the simulation: never rolls back
  onFailure: showDisconnected // a peer left, or runs another version
})
```

Rendering sees a rollback as ordinary changes: a shot undone and redone is a
shot that moved, so its sprite stays put.

## What a rollback would break does not compile

A rollback runs ticks again, so whatever they do runs again. A service that
is not input, plain data, or rewindable (audio, say) would act twice, and
state a system keeps in `local` would not come back. The session refuses
both:

```ts twoslash
import { Clock, Descriptor, HostClock, Schema } from "@typeonce/ritmo"
import { InputCapture } from "@typeonce/ritmo-browser"
import { Netcode, type NetworkLink } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats")
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })
declare const seats: Netcode.Seats<PlayerInput>
declare const link: NetworkLink.NetworkLink
const runtime = Game.Runtime.make({ services: Game.Runtime.services(Game.Runtime.service(Seats, seats.source)), resources: { Inputs: [] } }).value
const options = { seats, seat: 0, links: [link], hostClock: HostClock.standard, step: Clock.hz(60) }
// ---cut---
const Combo = Game.System(
  "Game/Combo",
  { local: () => ({ hits: 0 }) },
  ({ local }) => {
    local.hits++
  }
)

// @errors: 2375
Netcode.rollback(runtime, {
  ...options,
  simulate: Game.Schedule(Capture, Combo)
})
```

A physics engine that keeps its own world becomes a service with
`Checkpoint.rewindable`, saved and restored with every rollback.

## Sounds play once

A tick run again publishes its events again. The session hands the host
each event in three streams: `confirmed` once its tick can no longer change,
`predicted` while it may, and `withdrawn` for ticks a rollback undid.

```ts twoslash
import { Descriptor } from "@typeonce/ritmo"
import type { Netcode } from "@typeonce/ritmo-netcode"
const Hit = Descriptor.Event<{ readonly kind: "body" | "shield"; readonly x: number }>()("Game/Hit")
declare const session: Netcode.Session<unknown, never, typeof Hit>
declare const sounds: { readonly play: (kind: "body" | "shield") => void }
declare const particles: { readonly burst: (tick: number, x: number) => void; readonly cancel: (tick: number) => void }
// ---cut---
const hits = session.events(Hit)

// Every frame, after the session advanced:
for (const { tick } of hits.withdrawn()) particles.cancel(tick)
for (const { tick, value } of hits.predicted()) {
  particles.burst(tick, value.x) // at once, cancelled if undone
}
for (const { value } of hits.confirmed()) {
  sounds.play(value.kind) // exactly once
}
```

## Peers agree, or say so

Every 30 ticks, the peers compare a checksum of a tick all real input has
reached. A mismatch means the game is not deterministic somewhere:
the session reports `Desynced`, and `session.update` resyncs every peer
from seat 0's world. `session.status()` shows how far they agree, for a HUD or a test.

A hidden tab tells the others, who wait for it or play on without it,
instead of ending the match.

A [sync test](/features/bugs/#rollback-checked-on-every-tick) finds a desync
in a test run instead, on the tick it starts. Matches hold across machines
because the game is the [same everywhere](/features/determinism/).
