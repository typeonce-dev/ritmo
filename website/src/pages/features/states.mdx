A fighter is on the ground or in the air, never both. With Ritmo the type
says so too: each state carries only its own fields, and a move between
states must write the new state whole.

## What you get

- A value that pairs a state with another state's data does not compile.
- Moving to a new state takes every field it needs and nothing from the
  old one.
- Only the moves you allow exist. `to` offers only the states the graph
  permits from `from`.
- Every write checks the state it expects first, and says what it found
  when the entity has already moved on.
- Saved games and snapshots are checked state by state when they load.

## The bug it removes

A fighter in a test game started drifting up after a guard. Everything
about its body lived in one record:

```ts
interface Body {
  readonly grounded: boolean // [!code highlight]
  readonly vy: number // [!code highlight]
  readonly platform: number | null
  readonly coyote: number
}
```

The guard set `vy: 2` and left `grounded: true`. Gravity skips a grounded
body, so nothing pulled it back down. The record could describe a body on
the ground and moving up, and one day it did.

## One state, its own fields

`Descriptor.EntityState` gives each state only the fields it has:

```ts twoslash title="schema.ts"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
// ---cut---
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"

// `codec` is the game's Effect helper
// (see Concepts, "Validating and saving values")
const Contact = Descriptor.EntityState("Brawl/Contact", {
  // On the ground: the platform underfoot (null for the floor)
  ground: codec(S.Struct({ platform: S.NullOr(S.Int) })),

  // In the air: the only place a vertical speed exists
  air: codec(S.Struct({ vy: S.Finite, coyote: S.Int })) // [!code highlight]
}, {
  // The moves allowed between states
  transitions: { ground: ["air"], air: ["ground"] }
})

// The value is one of the states, named by `_tag`
type ContactValue = Descriptor.EntityStateOf<typeof Contact>
//   ^?
```

A grounded body with a `vy` no longer has a type to be. Each state's data
is one schema from the game's schema library, so a saved game is checked
state by state when it loads.

## Moving takes the new state's fields

A system moves an entity with `transition`. It writes the target state from
scratch: every field the target needs, and nothing from the state it
leaves.

```ts twoslash title="breaker.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
const Contact = Descriptor.EntityState("Brawl/Contact", {
  ground: codec(S.Struct({ platform: S.NullOr(S.Int) })),
  air: codec(S.Struct({ vy: S.Finite, coyote: S.Int }))
}, { transitions: { ground: ["air"], air: ["ground"] } })
const Game = Schema.bind(Schema.fragment({ components: { Contact } }))
const Bodies = Game.Query({ selection: { contact: Game.Query.write(Contact) } })
// ---cut---
// @errors: 2741
Game.System("Brawl/Breaker", { queries: { bodies: Bodies } }, ({ queries }) => {
  for (const { data } of queries.bodies.each()) {
    // Pops the fighter up: it is in the air now, with a speed to fall from
    data.contact.transition({
      from: "ground",
      to: "air",
      data: { vy: 2, coyote: 0 }
    })

    // Landing needs the platform it lands on
    data.contact.transition({ from: "air", to: "ground", data: {} })
  }
})
```

Staying in a state is `update`: it changes that state's fields, and only
those.

```ts twoslash title="fall.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
const Contact = Descriptor.EntityState("Brawl/Contact", {
  ground: codec(S.Struct({ platform: S.NullOr(S.Int) })),
  air: codec(S.Struct({ vy: S.Finite, coyote: S.Int }))
}, { transitions: { ground: ["air"], air: ["ground"] } })
const Game = Schema.bind(Schema.fragment({ components: { Contact } }))
const Bodies = Game.Query({ selection: { contact: Game.Query.write(Contact) } })
// ---cut---
// @errors: 2322
Game.System("Brawl/Fall", { queries: { bodies: Bodies } }, ({ queries }) => {
  for (const { data } of queries.bodies.each()) {
    data.contact.update({
      state: "air",
      data: (air) => ({ ...air, vy: air.vy - 0.6 })
    })

    // A field of another state is caught, even through a spread
    data.contact.update({
      state: "air",
      data: (air) => ({ ...air, platform: 1 })
    })
  }
})
```

Both are a compare-and-set: they write only while the entity is still in
the state they expect. Otherwise they return an `EntityStateMismatch`
failure that says which state it was in.

The editor completes each part: `from` offers every state, `to` only the
moves the graph allows, and `data` the target's fields.

## The one gap, and its lint

Game code written as pure functions builds the new value itself. Spreading
the old state and changing `_tag` compiles, because TypeScript does not
check the fields a spread brings along, and the old fields survive. The
lint rule names it:

```text
error ritmo(no-state-spread): This sets `_tag` over a spread of `air`: every
field of the previous state survives at runtime, though the type of the new
state hides it, so it comes back when the value is saved, compared, or
spread again. Move an entity state with `cell.transition({ from, to, data })`,
which takes the new state's fields; anywhere else, write the new state's
fields out: `{ _tag: "air", vy, coyote }`.
```

## What it buys

- Whole kinds of bug stop compiling: hitstun outside a hit, a hit flag left
  over from the last attack, a grounded body that drifts.
- Reading a value narrows on `_tag`, so code that uses a state's data runs
  only in that state.
- An entity state is a component like any other: it is saved, traced, and
  rolled back with the rest of the world, so
  [online play](/features/rollback/) and [replays](/features/replays/) keep
  it exact.
- When the fighter test game moved its body and action records to entity
  states, it played back bit for bit the same. The only casualty was a
  branch that could never run, which the old record had hidden.

An entity state is per entity. One mode for the whole game (menu, playing,
paused) is a state machine, which changes at a known point in the tick and
gates systems: see [Concepts](/docs/concepts/#state-machines). For
components that come and go, see
[Entities that change shape](/features/composition/).
