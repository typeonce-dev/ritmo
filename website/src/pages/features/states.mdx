A fighter is on the ground or in the air, never both. A flat record lets it
be both, and one day it is.

<Game id="states" ratio="16 / 9" />

The same script plays both fighters: a jump, a landing, a guard. The guard
sets a small upward speed. On the left it lands on a body that is still
`grounded`, gravity skips it, and it rises for good. On the right there is
no speed on the ground to set.

<Claim title="A grounded body with a speed has no type to be">

`Descriptor.EntityState` gives each state only the fields it has. Hover
`ContactValue`: it is one state or the other, never a mix.

```ts twoslash title="schema.ts"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
// ---cut---
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"

// `codec` is the game's Effect helper
// (see Concepts, "Validating and saving values")
const Contact = Descriptor.EntityState("Brawl/Contact", {
  // On the ground: the platform underfoot (null for the floor)
  ground: codec(S.Struct({ platform: S.NullOr(S.Int) })),

  // In the air: the only place a vertical speed exists
  air: codec(S.Struct({ vy: S.Finite, coyote: S.Int })) // [!code highlight]
}, {
  // The moves allowed between states
  transitions: { ground: ["air"], air: ["ground"] }
})

// The value is one of the states, named by `_tag`
type ContactValue = Descriptor.EntityStateOf<typeof Contact>
//   ^?
```

</Claim>

<Claim title="Moving writes the new state whole">

`transition` takes every field the target state needs, and nothing from the
state it leaves. Landing without the platform underfoot does not compile.

```ts twoslash title="breaker.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
const Contact = Descriptor.EntityState("Brawl/Contact", {
  ground: codec(S.Struct({ platform: S.NullOr(S.Int) })),
  air: codec(S.Struct({ vy: S.Finite, coyote: S.Int }))
}, { transitions: { ground: ["air"], air: ["ground"] } })
const Game = Schema.bind(Schema.fragment({ components: { Contact } }))
const Bodies = Game.Query({ selection: { contact: Game.Query.write(Contact) } })
// ---cut---
// @errors: 2741
Game.System("Brawl/Breaker", { queries: { bodies: Bodies } }, ({ queries }) => {
  for (const { data } of queries.bodies.each()) {
    // Pops the fighter up: it is in the air now, with a speed to fall from
    data.contact.transition({
      from: "ground",
      to: "air",
      data: { vy: 2, coyote: 0 }
    })

    // Landing needs the platform it lands on
    data.contact.transition({ from: "air", to: "ground", data: {} })
  }
})
```

</Claim>

<Claim title="Another state's field does not compile, even through a spread">

Staying in a state is `update`, and it changes only that state's fields.
Both writes check the state first: an entity that already moved on returns
an `EntityStateMismatch` that says where it is.

```ts twoslash title="fall.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], "~encode": S.toStandardSchemaV1(S.flip(json)) }
}
const Contact = Descriptor.EntityState("Brawl/Contact", {
  ground: codec(S.Struct({ platform: S.NullOr(S.Int) })),
  air: codec(S.Struct({ vy: S.Finite, coyote: S.Int }))
}, { transitions: { ground: ["air"], air: ["ground"] } })
const Game = Schema.bind(Schema.fragment({ components: { Contact } }))
const Bodies = Game.Query({ selection: { contact: Game.Query.write(Contact) } })
// ---cut---
// @errors: 2322
Game.System("Brawl/Fall", { queries: { bodies: Bodies } }, ({ queries }) => {
  for (const { data } of queries.bodies.each()) {
    data.contact.update({
      state: "air",
      data: (air) => ({ ...air, vy: air.vy - 0.6 })
    })

    // A field of another state is caught, even through a spread
    data.contact.update({
      state: "air",
      data: (air) => ({ ...air, platform: 1 })
    })
  }
})
```

</Claim>

<Claim title="The one gap is a lint error">

Pure functions that build the next value can spread the old state and change
`_tag`. TypeScript lets it through; the lint names it and the fix.

```text title="oxlint"
error ritmo(no-state-spread): This sets `_tag` over a spread of `air`: every
field of the previous state survives at runtime, though the type of the new
state hides it, so it comes back when the value is saved, compared, or
spread again. Move an entity state with `cell.transition({ from, to, data })`,
which takes the new state's fields; anywhere else, write the new state's
fields out: `{ _tag: "air", vy, coyote }`.
```

</Claim>

<Claim title="Saved, replayed, and rolled back like any component">

An entity state is a component: snapshots check it state by state when they
load, and [replays](/features/replays/) and
[online play](/features/rollback/) keep it exact. When the fighter test game
moved its bodies to entity states, it played back bit for bit the same. The
only casualty was a branch that could never run.

</Claim>

One mode for the whole game (menu, playing, paused) is a state machine: see
[Concepts](/docs/concepts/#state-machines). For components that come and go,
see [Entities that change shape](/features/composition/).
