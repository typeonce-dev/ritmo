Ritmo runs the simulation of a game that coding agents write. It is not a
game engine: drawing, sound, saving, servers, and platform SDKs stay in the
game, which plugs them in through typed contracts, the way it brings its own
schema library. This page lists what Ritmo added from its roadmaps, what it decided not
to add, and what comes next.

An addition has to pass one test: **it is only right when it is built into
the runtime.** Access declarations, per-reader streams, the fixed step,
checkpoints and rollback, or the devtools trace have to know about it. A
piece a game can get from an existing library behind a small typed contract
is a playbook in the [skill](/docs/with-an-agent/), not a package. A piece
that is gameplay stays in the game.

One package is the exception: `ritmo-math` holds the 2D helpers most
games would otherwise rewrite, as plain data in and plain data out, built
on `Ops` so they replay the same on every engine. It never ports a
third-party algorithm, and determinism alone is never a reason to add one:
`Ops` and `oxlint --fix` already make any game math deterministic. A helper
gets in when at least two games hand-roll it, it takes and returns plain
data, and it sits beside what is there (`Vec2`, `Box2`, `Segment2`,
`Collide2`, `FlowField`).

Every item keeps the rules of the rest of the library: wrong code does not
compile, a failure that depends on runtime state is a typed `Result`, and
there is one way to do each thing. Type safety wins over speed.

## Shipped

The second wave, in one change: [#111](https://github.com/typeonce-dev/ritmo/pull/111).

- **`Ops` and `Random` in the core.** Imported from `@typeonce/ritmo`; the `Ops` list is closed (22 functions and `**`).
- **`oxlint --fix` does the whole job.** `ritmo/use-ops-for-math` adds the `Ops` import and fixes `**=`; aliasing `Math` is reported; `ritmo/no-brand-cast` reports a cast to a branded type.
- **A smaller `ritmo-math`.** `Vector2`, `Size2`, `Aabb`, the validated `Scalar` brands, and `InputAxis` are gone (the game's schema validates); the spatial grid is a playbook in the skill; `FlowField.make` returns a typed failure.
- **Math every game rewrites.** `Angle.wrap` and `turnToward`; `Vec2.perpendicular`, `fromAngle`, `angle`, `decayToward`; `Scalar.moveToward`, `lerp`, `decayToward`; `Box2.closestPoint`; `Collide2.overlapsCircleCircle`.
- **One replay check.** `Verify.acrossEngines` replaces `Replay.verify`; the committed cross-engine replay now runs `Ops`.
- **A scan of the dependencies.** `ritmo-devtools scan <entry>` lists the non-exact math, randomness, and wall time in every package the simulation imports.
- **Branding and third-party code in the skill.** Brands come from the game's schema library, never a cast; a decision order for libraries, from the scan to vendoring to `Checkpoint.rewindable`.

Every item of the first roadmap is in `main`, in the order it landed.

- **Seeded fuzzing that shrinks to a test.** `Fuzz.input`, `Fuzz.run`; a found bug is a shrunk replay `Replay.session` plays to the same violation. [#95](https://github.com/typeonce-dev/ritmo/pull/95)
- **Step-counted deadlines, and a lint for float timers.** `Clock.Deadline`, `deadline`, `reached`, `remaining`, `isDeadline`, and `ritmo/no-float-timers`. [#94](https://github.com/typeonce-dev/ritmo/pull/94)
- **Entity labels in devtools output.** A `labels` inspector on `Session.make`, `Replay.session`, `Determinism.check`; a labels map on `Desync.compare`. [#96](https://github.com/typeonce-dev/ritmo/pull/96)
- **Rewindable services.** `Checkpoint.rewindable` admits a library that keeps its own world into a rewound schedule. [#97](https://github.com/typeonce-dev/ritmo/pull/97)
- **Browser input that replays and fuzzes.** `InputCapture.SourceOf`, `actions.random`, `players.random`; one controls descriptor for the page, replays, and the fuzzer. [#98](https://github.com/typeonce-dev/ritmo/pull/98)
- **Determinism checked across engines.** `ritmo-devtools verify` and `Verify.acrossEngines` over Node, Chromium, WebKit, and Firefox, with a CI job. [#101](https://github.com/typeonce-dev/ritmo/pull/101)
- **Remove the live browser monitor.** Debugging is headless and text-first; devtools drops its DOM dependency. [#104](https://github.com/typeonce-dev/ritmo/pull/104)
- **Children attached to their parent's node.** `RenderSync` takes a `Descriptor.Hierarchy`; `NodeRegistry.attach` gains the parent. [#109](https://github.com/typeonce-dev/ritmo/pull/109)
- **Confirmed, predicted, and withdrawn event streams.** `session.events(Event)` with `confirmed()`, `predicted()`, `withdrawn()`, `lost()`. [#100](https://github.com/typeonce-dev/ritmo/pull/100)
- **Stepping one system at a time.** `session.step(schedule)` with `until`, `next`, `check`, `finish`, on a `debug.beginFrame` cursor. [#108](https://github.com/typeonce-dev/ritmo/pull/108)
- **A stream of relations dropped by a despawn.** `Game.System.readDroppedRelations(Relation)`, per reader, once. [#107](https://github.com/typeonce-dev/ritmo/pull/107)
- **Descriptor metadata.** A `meta` option (unit, range, hint) typed against the schema's fields; an `out-of-range` report warning. [#105](https://github.com/typeonce-dev/ritmo/pull/105)
- **A policy for hidden tabs.** A `Visibility` contract, `BrowserVisibility`, `MemoryVisibility`, the `hidden` option, `status().hidden`. [#102](https://github.com/typeonce-dev/ritmo/pull/102)
- **`why` that follows the reads.** A `depth` option on `why` and `whyResource`, through declared reads. [#103](https://github.com/typeonce-dev/ritmo/pull/103)
- **Adaptive input delay.** `adaptiveDelay: { min, max }`, per seat, with `status().inputDelay`. [#106](https://github.com/typeonce-dev/ritmo/pull/106)
- **Sync-test session, with network-fault fuzzing.** `Netcode.syncTest`, and `Fuzz.run` with `network` and `Fuzz.seats`. [#99](https://github.com/typeonce-dev/ritmo/pull/99)

## Left to the game, on purpose

These came up in the survey behind this page and were set aside. Each is a
real need; none needs the runtime to be done right.

- **Saving, servers, lobbies, relays.** `runtime.snapshot()` is the save; where
  it goes is the game's. Netcode works over any `NetworkLink`; who connects
  whom is the game's.
- **Audio, haptics, analytics.** Host code that acts on confirmed events.
- **Platform SDKs** (web portals, Discord, Steam, mobile shells). Services the
  game provides, like any other.
- **Renderer adapters beyond Pixi.** A `NodeRegistry` for Three.js is a few
  lines; the skill will show them.
- **Physics engines, pathfinding, geometry, noise, curves, grids.** Libraries
  the game brings. The rewindable service contract above is the one hook
  they need from Ritmo, and `ritmo-devtools scan` says whether one calls
  math that differs across engines (then the game vendors it and runs
  `oxlint --fix`). `ritmo-math` keeps to the 2D helpers most games rewrite;
  it does not port a library's algorithms.
- **Gameplay bundles** (stats, status effects, inventory, dialogue, cameras,
  spawners). Systems the agent writes, with playbooks for the common shapes.
- **Observers and lifecycle hooks, system sets with automatic ordering.** Each
  is a second way to do something the schedule and per-reader streams
  already do explicitly.
- **Faster storage at the cost of types.** Storage is already paged typed
  arrays for numbers behind typed cells. No raw store access will be exposed.
- **An MCP server, hot reload of systems.** Agents drive a `Session` from a
  script today; a system swapped under a running world has no owner for its
  state.

Several of these become playbooks in the skill instead: scene data spawned
into an `EntityScope`, templates as spawn drafts, menu and gameplay input
contexts from `Controls` and run conditions, separate `Random` resources per
subsystem, a camera that follows, and saves over snapshots.

## Next

Recorded, and waiting for a reason:

- **A name for `ritmo-math`.** It now holds 2D helpers only; whether it
  becomes `ritmo-2d` is open.
- **Rewriting `Math.` in named dependencies at build time.** A Vite
  transform, only if vendoring proves painful again and again. It would
  replace vendoring as the one way, never sit beside it.
- **A relation edge-change filter for `RenderSync` hierarchies.** Waits for
  a measured regression.

Rejected: patching the global `Math` at runtime (global, depends on import
order, and misses WebAssembly), and a compile-time ban of `Math.sin` and
the like (TypeScript cannot narrow a global per file).

## How this page was made

A survey of what ECS runtimes, engines, physics and netcode libraries, and
devtools offer (Bevy, flecs, Unity DOTS, bitECS, Koota, Rapier, Box2D, GGRS,
Lightyear, Phaser, Godot, and others), filtered through two independent
scope reviews against the rules above. Open an
[issue](https://github.com/typeonce-dev/ritmo/issues) to argue for an item,
or against one.
